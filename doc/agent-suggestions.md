# agent의 제안

작업 중 발견한 추가 기능·개선안을 분류별 목록으로만 관리합니다. 기록은 구현 승인이나 확정 계획을 의미하지 않습니다. 사용자 승인 전에는 구현하지 않습니다.

항목은 `제안 내용 — 간단한 이유` 형식으로 작성하고, 기존 항목과 중복되면 통합합니다. 이미 합의된 구현 계획과 TODO는 해당 문서에서 관리하며 여기에 중복 나열하지 않습니다.

## 기능·사용성

현재 제안 없음.

## 구조·유지보수

현재 제안 없음.

## 성능·운영

- 이미지 업로드의 요청 전체 최대 용량을 파일당 제한과 함께 관리 — multipart 부가 데이터를 포함하므로 파일당 최대 용량보다 여유가 필요하며 현재 spring.servlet.multipart.max-request-size를 사용함.
- 허용 이미지 형식을 YAML 설정으로 분리 — 현재 PNG·JPEG·GIF·BMP를 코드에서 제한하며 운영 정책에 맞춰 허용 목록을 바꿀 수 있게 함. 디코더가 실제 지원하는 형식 안에서만 허용해야 함.
- 이미지 최대 화소 수를 YAML 설정으로 분리 — 현재 4천만 화소 제한을 서버 메모리·처리 용도에 맞춰 조정할 수 있게 함.
- 다중 업로드의 동시 처리 수·최대 파일 개수는 다중 업로드 UI 또는 서버 묶음 API 도입 시 설정 후보로 검토 — 현재 백엔드는 파일당 단건 요청이므로 선제적으로 설정·구현하지 않음.

## 개발 편의·보조 기능

- 기존 프런트 프록시 테스트 fixture에 필수 FrontendPort 설정 보완 — local-proxy.test.mjs가 BackendPort만 작성해 현재 Vite 설정을 로드하지 못함. 이번 생성 화면에서는 실행 설정·테스트 도구 범위를 확대하지 않고 기존 실패로 기록함.

- Maven의 불필요한 외부 저장소 메타데이터 조회 정책 정리 — Flyway 부모 POM에서 유입된 인증 필요 저장소의 `prefixes.txt` 조회가 401 경고를 발생시킴. 의존성 해석에 미치는 영향을 확인한 뒤 승인받아 설정하며 단순 로그 숨김으로 처리하지 않음.
- 기동 시 API에 선언된 권한 중 DB에 없는 항목을 자동 등록 — 새 API 추가 시 권한 등록 누락을 줄임. 자동 등록은 권한 정의에 한정하고 역할·사용자에게 권한을 자동 부여하지 않음. 사용자 승인 전에는 구현하지 않음.
