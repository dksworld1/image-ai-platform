- 관련 문서: [개발 계획](../plans/roadmap.md), [기능 구현 단계](README.md), [백엔드 기반](stage-01-backend-foundation.md)
- 관련 결정: [ADR-014 클래스 초기화 기반 런타임 설정과 정적 접근](../decisions/ADR-014-static-runtime-settings.md)

## 목표와 사용자 가치

백엔드 개발 계획에서 누락된 애플리케이션 설정 모듈을 구현합니다. 남은 인증·권한 및 제품 기능 개발보다 먼저 진행합니다.

## 범위와 제외 범위

- 대상 설정 항목과 모듈의 책임을 정의한 뒤 필요한 기능을 구현합니다.
- 일반 애플리케이션 설정은 Spring YAML 파일로 관리하며 프로젝트 설정에 환경 변수를 사용하지 않습니다.
- Spring 초기화 전 필요한 런타임 설정은 주제별 UTF-8 `.properties` 파일로 분리합니다. 중앙 로더, 불변 설정 객체, 정적 접근점으로 구성합니다.
- 클래스패스 `config/runtime/` 바로 아래의 모든 `*.properties`를 자동 로딩하며 하위 디렉터리는 제외합니다. 중복 키·중복 리소스는 오류 처리하고 IDE·패키징된 JAR 실행을 모두 지원합니다.
- 새 설정은 불변 설정 객체에 명시적 필드를 추가하고 중앙 로더의 매핑을 함께 추가합니다. 소비자에게 문자열 키 기반 동적 조회를 제공하지 않습니다.
- YAML은 가능한 한 주제별 파일로 분리하고 `spring.config.import`로 조합합니다. 비밀값이 포함된 YAML은 저장소 밖에서 관리합니다.
- 런타임 설정은 클래스 최초 사용 시 정적 필드 초기화로 로딩하며 `main()`의 초기화 호출은 사용하지 않습니다. 실행 중 변경·재로딩은 제공하지 않습니다.
- 기존 Spring 프로파일·JDBC·로그 설정과의 관계를 확인하고, 기존 환경 설정을 대체하는지는 별도로 결정합니다.

## 선행 조건과 영향

1단계의 백엔드 기반을 사용합니다. 기존 단계 번호는 유지하며 설정 모듈 개발을 우선 진행합니다. 다른 모듈과의 구체적인 의존 관계는 설정 범위를 정한 뒤 기록합니다.

## 핵심 개념과 원리

실행 환경을 구성하는 설정과 애플리케이션 기능에서 관리할 설정의 경계를 먼저 정합니다. 설정값의 저장 위치와 실제 적용 시점을 구분해 정의합니다.

`RuntimeSettingsLoader`가 문자열 키를 명시적 타입의 `RuntimeSettings` 필드로 매핑하고, `RuntimeConfig`가 `private static final` 필드에 보관해 `settings()`로 제공합니다. 일반 메서드와 정적 메서드·필드·블록 모두 같은 접근점을 사용합니다. Spring과 독립적으로 로딩하며 순환 초기화를 금지합니다. 상세 클래스 책임·초기화 순서·실패 정책은 ADR-014를 따릅니다.

## 데이터·API·권한·오류 처리

런타임 설정은 프로세스 내부 정적 접근으로 제공하며 이를 위한 HTTP API는 추가하지 않습니다. 필수 파일·값 누락이나 형식 오류는 클래스 초기화 실패로 처리하며 비밀값은 오류에 노출하지 않습니다. 일반 애플리케이션 설정의 API 필요 여부와 권한은 아직 미결정입니다.

## 미결정 질문과 후속 조치

- 관리할 설정 항목과 모듈 책임 범위를 정의합니다.
- 주제별 YAML 구성, 외부 비밀 설정 파일 로딩 방식, 조회·변경 주체 및 적용 시점을 정합니다.
- 새 설정은 YAML과 명시적 실행 옵션으로 관리합니다.
- 범위 확정 후 필요한 데이터·API·권한 계약과 자동 검증 항목을 구체화합니다.

- [ ] UTF-8 파일 로딩·타입 변환·필수값 검증 및 정적 최초 접근·동시 접근·초기화 실패를 자동 검증했습니다.

- [ ] 동작에 대한 자동 검증을 실행하고 결과를 기록했습니다.
- [ ] 구현에 따른 관련 기준 문서를 갱신했습니다.

### 현재 구현

- `foundation.config`에 `RuntimeSettingsLoader`, `RuntimeSettings`, `RuntimeConfig`를 구현했습니다. `main()` 변경 없이 최초 정적 접근 시 한 번 로딩합니다.
- 기존 의존성인 Spring Core의 리소스 탐색 유틸리티를 사용하며 Spring 컨테이너·빈·Environment는 사용하지 않습니다. properties 해석은 Java 표준 API로 수행합니다.
- 디렉터리 엔트리가 없는 일반 JAR은 URLClassLoader의 JAR 항목을 보완 탐색합니다. 파일명 정렬, 중복 리소스·키 검사, 하위 디렉터리 제외를 적용했습니다.
- 실제 설정 항목은 미정이므로 `RuntimeSettings`는 현재 필드 없는 record이며 `config/runtime/runtime.properties`에는 안내 주석만 있습니다. 새 설정을 추가할 때 필드·매핑·타입 변환·필수값 검증을 함께 구현합니다. 현재 필수 파일·필수 키는 없으므로 설정 파일이 없어도 빈 설정 객체를 만들 수 있습니다.
- 환경 변수 참조를 제거하고 외부 YAML 로딩을 검증했습니다. 설정 모듈 전체 완료와 런타임 접근 구조 구현을 구분합니다.
- 런타임 로더는 INFO로 클래스패스 탐색 폴더·패턴과 각 파일의 로딩 완료 위치(URL)를 기록합니다. 디렉터리·JAR 내부 경로를 구분할 수 있으며 설정값은 기록하지 않습니다. 대상 폴더가 없거나 바로 아래에 properties 파일이 없으면 설정을 사용하려면 클래스패스 `config/runtime/` 폴더와 UTF-8 `.properties` 파일을 생성하라는 WARN을 출력하고 빈 설정 허용 동작은 유지합니다. 기존 SLF4J 로거를 사용하며 별도 로깅 설정은 추가하지 않습니다.

### 검증 결과

- 2026-11-07 로그 추가 후: Java 21.0.13·Maven 3.10.0으로 `mvn test` 전체 41개 통과. 디렉터리의 파일별 위치와 JAR 내부 파일별 위치 출력, 설정값 비노출, 폴더 없음·properties 파일 없음 각각의 WARN 생성 안내를 확인했습니다. 신규 로그 테스트의 구문 오류를 수정한 후 재실행한 결과입니다.
- 2026-11-07: Java 21.0.13·Maven 3.10.0을 확인한 동일 PowerShell 세션에서 `mvn test` 실행, 전체 38개 통과(실패·오류·건너뜀 0).
- 신규 테스트 8개: 여러 파일 UTF-8 통합, 하위 디렉터리·다른 확장자 제외, 디렉터리 엔트리가 없는 일반 JAR 로딩, 파일 내·파일 간 중복 키, 클래스패스 간 중복 리소스, 잘못된 properties 값의 오류 처리, 빈 설정 허용, 격리 클래스 로더의 동시 최초 접근 및 초기화 실패 후 재접근을 확인했습니다.
- 최초 실행은 Maven 캐시 잠금 파일 접근 제한으로 중단됐으며 권한을 허용한 재실행에서 검증했습니다. 중간 실행에서 발견한 일반 JAR 탐색 누락과 Windows JAR 파일 핸들 캐시 문제를 수정한 뒤 위 전체 테스트가 통과했습니다.
- 실제 설정 항목의 타입 변환·필수값 검증 및 Spring Boot 실행 JAR의 중첩 리소스 로딩은 아직 검증하지 않았습니다.
