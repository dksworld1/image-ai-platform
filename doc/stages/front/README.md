## 구현 단계

프런트 내부 단계는 F1~F5로 구분합니다. 백엔드 단계 번호와 별개이며 전체 진척도에서는 기존처럼 프런트를 한 건으로 집계합니다. F1의 화면 골격 구현에 착수했으며 나머지 단계는 계획 상태입니다.

| 단계 | 주요 범위 | 선행 조건 | 완료 기준 | 상태 |
|---|---|---|---|---|
| [F1. 화면 기반 구성](stage-01-screen-foundation.md) | 기본 레이아웃, 탐색 영역, 화면 이동, 기본 시각 스타일, API 호출 경계 | 첫 화면 범위·URL·대상 화면 크기 결정 | 합의한 화면 이동과 레이아웃 동작, 헬스체크 로딩·정상·실패 표시 확인 | 구현 중 |
| F2. 인증과 접근 흐름 | 로그인, 토큰 전달, 로그아웃, 만료·401·403 안내 | F1, 기존 로그인 API, 토큰 저장·로그인 유지 정책 결정 | 로그인 성공·실패, 로그아웃, 보호된 요청과 재로그인 흐름 검증 | 계획 |
| F3. 데이터셋과 이미지 탐색 | 데이터셋 목록·상세, 이미지 목록·상세, 메타데이터 표시 | F2, 백엔드 3단계의 조회·권한 계약, 이미지 제공 방식 확정 | 접근 가능한 데이터 탐색과 상세 확인, 빈 결과·조회 실패·접근 불가 검증 | 계획 |
| F4. 수집과 업로드 | 입력 선택·등록, 진행 및 개별 성공·실패 결과 표시, 데이터셋 화면 연결 | F3, 백엔드 4단계의 입력·제한·전송·결과 계약 확정 | 등록한 이미지가 데이터셋에서 확인되고 실패 항목과 후속 행동을 구분 | 계획 |
| F5. 이미지 작업과 결과 검토 | 전처리, 레이블링, 클러스터링, 플러그인 처리 화면 | F3, 각 기능의 백엔드 5~8단계 계약. 입력 이미지가 없으면 F4 필요 | 기능별 입력·실행 또는 저장·결과 검토와 실패 흐름 검증 | 계획 |

F1 → F2 → F3 → F4 → F5를 기본 순서로 진행합니다. F5는 하나의 큰 단계로 묶되 전처리·레이블링·클러스터링·플러그인을 각각 독립적으로 완료 처리합니다. 기능 간 세부 순서는 사용 우선순위와 백엔드 준비 상태에 따라 정합니다.

각 단계는 구현 시 해당 기능의 자동 검증과 `typecheck`·`build`, 키보드 조작 및 화면 배치 확인을 함께 수행합니다. 검증을 별도 마지막 단계로 미루지 않습니다. 세부 정책과 공통 완료 조건은 [화면과 사용자 흐름 설계](design.md)를 따릅니다.

## 관리 원칙

- 공통 설계는 현재 설계 문서에서 관리하고, 주제별 상세 설계가 필요해지면 이 디렉터리에 문서를 추가하고 목록에 연결합니다.
- 업무 규칙과 API 계약은 해당 기능 단계 및 기준 문서를 참조하며 중복 정의하지 않습니다.
- 미결정 사항과 채택한 결정을 구분하고 중요한 구조·의존성 결정은 `doc/decisions/`의 ADR과 연결합니다.
- 문서 추가 자체는 기능 구현이나 의존성 도입 승인을 의미하지 않습니다.
