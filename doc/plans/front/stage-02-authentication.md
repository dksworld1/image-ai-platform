# F2단계: 로그인과 접근 흐름

## 사용자 필드 전환 — 2026-11-10

로그인은 userId·password를 전송합니다. 서버 응답의 userKey·userId·username을 토큰·만료와 함께 보관하며 username은 실명 또는 null입니다. 헤더에는 로그인 아이디와 존재하는 실명을 각각 표시합니다. 이전 username 전용 저장값은 제거해 재로그인합니다. [ADR-031](../../decisions/ADR-031-user-identity-fields.md)을 따릅니다. 아래 기존 username 저장 설명은 당시 이력입니다.

검증: 프런트 자동 테스트 15개와 타입 검사 포함 빌드 통과. Edge headless에서 userId 요청·서버 식별정보 저장·로그인 아이디와 실명 분리 표시·새로고침 복원·로그아웃·구 세션 제거를 확인했습니다. 브라우저의 인증 응답은 테스트 대체이며 실제 로그인·DB 처리는 백엔드 통합 테스트에서 검증했습니다.

## 기존 UI 모듈 철거 — 2026-11-09

[ADR-027](../../decisions/ADR-027-remove-ui-module.md)에 따라 기존 화면·메뉴 API, 서비스·DAO·도메인·매퍼와 프런트 동적 내비게이션을 제거했습니다. 아래 기존 UI 구현·검증 내용은 과거 이력이며 현재 제공 기능이 아닙니다. 로그인·세션·로그아웃과 공통 레이아웃은 유지합니다. 새 메뉴 구현은 별도 작업이며 URL은 React 코드에서, 숨김은 메뉴 렌더링에서 관리합니다.

- 상태: 구현 중
- 갱신일: 2026-11-08
- 선행 단계: F1 화면 골격, 기존 토큰 발급 API
- 관련 문서: [API 계약](../../api/api.md), [공통 프런트 설계](design.md), [ADR-025](../../decisions/ADR-025-tab-session-and-header-account.md)

## 목표와 사용자 가치

인덱스에서 로그인하고 서버가 발급한 토큰으로 후속 업무 화면을 사용할 기반을 마련합니다.

## 범위와 제외 범위

현재 로그인 화면·토큰 발급·내비게이션 조회·탭 세션 복원·로그아웃·만료 처리·헤더 아이디 표시를 구현했습니다. 후속 업무 API와 보호된 화면의 401·403 처리 및 라우팅은 후속 작업입니다. 회원가입·비밀번호 변경은 포함하지 않습니다.

## 선행 조건과 영향

활성 계정과 BCrypt 비밀번호 해시는 서버에 준비되어 있어야 합니다. UI에서 계정이나 권한을 자동 생성하지 않습니다. 로컬 프록시와 서버 설정은 변경하지 않습니다.

## 핵심 개념과 원리

- 유효한 탭 세션이 없는 인덱스 진입은 로그인 화면입니다. 로그인 전 업무 메뉴와 헬스체크 화면은 표시하지 않습니다.
- 입력에는 아이디·비밀번호 레이블과 자동완성 식별자를 제공합니다. 비밀번호는 가림 입력이며 공백을 임의로 제거하지 않습니다.
- 필수 입력이 없으면 제출할 수 없습니다. 제출 중 입력과 버튼을 비활성화하고 중복 요청을 막습니다.
- 성공하면 `App`에 토큰 응답을 보관하고 시작 화면을 표시합니다. 토큰·만료 시각·아이디는 sessionStorage에 저장하고 같은 탭에서 새로고침 시 복원합니다. 헤더 우상단에는 아이디와 로그아웃 버튼을 표시합니다.
- 비밀번호는 성공 후 지우고 영속 저장하거나 로그에 기록하지 않습니다.

## 데이터·API·권한·오류 처리

- `src/api/auth.ts`가 JSON 로그인 요청과 `AuthToken` 응답 타입을 소유합니다. 공개 로그인 요청에 Bearer 헤더를 붙이지 않습니다.
- 401은 계정 존재·비활성 여부를 구분하지 않고 동일한 자격 증명 확인 문구를 표시합니다.
- 네트워크 실패와 그 밖의 HTTP 실패를 구분해 안내하며 서버 오류 본문은 그대로 표시하지 않습니다. 실패 시 로그인 화면을 유지하고 재시도할 수 있습니다.
- 프런트 로그인 상태만으로 업무 접근을 허용하지 않으며, 후속 API의 인증·권한은 서버가 판정합니다.

## 미결정 질문과 후속 조치

- 사용자별 내비게이션, 실제 화면 이동과 보호된 API 토큰 전달을 연결합니다.
- 후속 업무 API의 토큰 전달과 서버가 거부한 인증·권한에 대한 401·403 처리 흐름을 구체화합니다.

## 완료 조건과 검증 결과

현재 로그인 범위의 자동 검증은 `frontend/`에서 `node --test test/login.test.cjs`로 실행합니다. 최초 화면, 로그인 요청·성공 응답, 401·서버 장애·네트워크 장애를 확인합니다. API는 mock 응답이며 실제 계정 인증과 브라우저 상호작용 검증을 대체하지 않습니다.

- 2026-11-08: 로그인 자동 검증 5개 통과, `npm run typecheck`, `npm run build` 성공.
- 실제 브라우저 제출·성공 화면 전환·키보드 조작·화면 크기별 배치 및 실제 서버 로그인은 아직 검증하지 않았습니다.
- F2 전체 완료에는 후속 업무 API의 토큰 전달과 보호된 요청의 401·403 검증이 추가로 필요합니다.

## 로그인 후 메뉴 표시 연동

- 2026-11-08: AppLayout이 로그인 토큰으로 GET /api/ui/navigation을 호출하도록 연결했습니다. 평면 메뉴를 parentMenuCode별로 묶고 sortOrder·menuCode 순으로 렌더링하며 부모 항목이 먼저 나온다고 가정하지 않습니다.
- 로딩·빈 메뉴·실패 안내와 다시 불러오기를 제공합니다. 화면 이탈 시 요청을 취소하고 이전 응답의 상태 갱신을 막습니다. 401은 재로그인 안내를 표시합니다.
- 시작 화면은 현재 위치로 표시합니다. 아직 React 화면이 없는 관리 메뉴는 준비 중으로 표시하고 비활성화합니다. 현재 시작 화면 링크는 일반 클릭 시 새로고침하지 않아 메모리 로그인 상태를 유지합니다. URL 라우팅·관리 CRUD UI는 미구현입니다.
- 검증: node --test test/login.test.cjs 9개 통과, npm run typecheck·npm run build 성공. 실제 실행 중인 로컬 백엔드에서 admin 로그인과 시작·관리 메뉴 4개 응답을 확인했습니다. 브라우저 렌더링·상호작용 확인은 수행하지 않았습니다.

## 탭 세션 복원·로그아웃·헤더 계정 정보

- sessionStorage의 image-ai-platform.auth에 accessToken·tokenType·expiresIn·expiresAt·username을 보관합니다. 비밀번호는 저장하지 않습니다. expiresAt은 응답 수신 시 정하고 새로고침에서 연장하지 않습니다.
- 유효한 저장값은 App 초기 상태로 복원하고 만료·손상된 값은 제거합니다. 화면에 머무르는 중에도 만료 시각에 상태를 해제합니다.
- 로그아웃 클릭은 저장값과 App 상태를 제거합니다. 헤더 우상단 사용자 정보는 로그인 시 사용한 아이디이며 표시 전용입니다. 이름·이메일 조회 API와 서버 토큰 폐기는 추가하지 않았습니다.
- 2026-11-08: node --test test/login.test.cjs 13개, npm run typecheck, npm run build 통과. 저장·복원·세션 제거·만료·손상값과 복원된 헤더 아이디·로그아웃 버튼을 정적 렌더링으로 확인했습니다. 실제 브라우저 새로고침·버튼 클릭과 타이머 만료 상호작용은 이번 검증에서 실행하지 않았습니다.

## UI 모듈 철거 검증 — 2026-11-09

- 프런트: `node --test frontend/test/*.test.cjs` 9개 통과, `npm --prefix frontend run build` 성공. 로그인·세션 복원·로그아웃·만료 처리는 유지하고 로그인 후 메뉴를 렌더링하지 않는 것을 확인했습니다.
- 백엔드: Java 21.0.13·Maven 3.10.0 확인 후 `mvn clean test`를 별도 메모리 DB에서 실행해 삭제 리소스를 정리했고, 최종 추가 검증을 포함한 `mvn test "-Ddatasource.app.url=jdbc:h2:mem:remove-ui-app;DB_CLOSE_DELAY=-1" "-Ddatasource.audit.url=jdbc:h2:mem:remove-ui-audit;DB_CLOSE_DELAY=-1"`에서 49개 통과, 실패·오류 0개.
- 신규 DB의 최종 UI 테이블 부재, 기존 V3 데이터의 V4 제거, UI 권한·역할 연결만 정리, 다른 권한 보존, 재적용 0건과 제거 API의 404 응답을 검증했습니다. 실제 로컬·운영 DB 마이그레이션이나 브라우저 검증은 실행하지 않았습니다.
