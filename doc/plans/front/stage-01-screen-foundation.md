# F1단계: 화면 기반 구성 세부 설계

- 상태: 구현 중
- 갱신일: 2026-11-08
- 선행 단계: 기존 React + TypeScript + Vite 골격
- 관련 문서: [프런트 구현 단계](README.md), [공통 설계](design.md), [현재 아키텍처](../../architecture/architecture.md), [API 계약](../../api/api.md)
- 관련 ADR: 없음. 화면 이동 방식과 신규 의존성은 채택 시 별도 판단

## 목표와 사용자 가치

사용자가 현재 위치와 이동 가능한 화면을 이해할 수 있는 화면 골격을 마련합니다. 이후 로그인과 데이터셋 화면이 같은 레이아웃·이동·상태 표시 원칙을 따르도록 최소 기반을 설계합니다.

이 문서의 구체적인 배치·경로·수치는 검토할 기본안입니다. 문서 작성은 제품 코드 구현이나 신규 의존성 도입 승인을 의미하지 않습니다.

## 범위와 제외 범위

| 구분 | F1 범위 | 후속 단계 |
|---|---|---|
| 화면 | 시작 화면, 업무 화면 골격, 찾을 수 없는 화면 | 로그인은 F2, 데이터셋·이미지 내용은 F3 |
| 탐색 | 제품명, 현재 위치, 화면 이동과 선택 표시 | 사용자 메뉴·로그아웃은 F2, 실제 업무 메뉴는 해당 기능 단계 |
| 스타일 | 배경·글자·간격·테두리·포커스의 최소 CSS 규칙 | 테마 전환, UI 라이브러리, 별도 디자인 시스템은 포함하지 않음 |
| 상태 | 기존 헬스체크의 로딩·정상·실패 표시 | 업무 데이터의 빈 결과와 제출 상태는 실제 화면 구현 시 적용 |
| API | 기존 헬스체크 호출 경계 유지 | 토큰·업무 API와 필요한 공통화는 F2 이후 |

개발용 상태 전환 화면, 예제 데이터 서버, 범용 폼·테이블·요청 프레임워크를 추가하지 않습니다. 없는 기능의 메뉴나 실행 버튼을 동작 가능한 것처럼 노출하지 않습니다.

## 선행 조건과 영향

- F1은 기존 공개 헬스체크만 사용하므로 백엔드 업무 API 완성을 기다리지 않습니다.
- F2의 로그인 화면은 업무 탐색 영역 없이 본문 중심으로 표시하고, F3부터 업무 레이아웃 안에 실제 내용을 연결하는 방향입니다.
- 인증 전후의 이동 제한은 F2에서 구현합니다. F1의 화면 이동 자체가 인증·권한 검사를 대신하지 않습니다.
- 직접 URL 접근과 새로고침 요구는 화면 이동 방식 및 정적 배포 설정에 영향을 줍니다. 배포 설정을 실제 변경할 때 운영 문서도 갱신합니다.

## 핵심 개념과 원리

### 1. 화면 골격

업무 화면의 기본 배치는 다음과 같습니다. 대시보드 지표나 별도 홈 업무 기능은 추가하지 않습니다.

```text
┌──────────────────────────────────────────────────┐
│ 제품명                                            │
├─────────────┬────────────────────────────────────┤
│ 탐색 영역   │ 현재 위치 / 화면 제목               │
│             │ 설명 및 해당 화면의 주요 행동        │
│ 현재 메뉴   ├────────────────────────────────────┤
│             │ 본문: 조회 결과 또는 화면 상태        │
└─────────────┴────────────────────────────────────┘
```

- 제품명은 시작 위치로 이동하는 링크입니다. 각 화면은 하나의 주 제목 `h1`을 가집니다.
- 업무 레이아웃은 헤더, 탐색 `nav`, 본문 `main`으로 구성합니다. 현재 메뉴는 텍스트·형태와 `aria-current="page"`로 구분합니다.
- F1에서는 시작 화면만 탐색에 연결합니다. 데이터셋 메뉴는 F3에서 실제 화면이 생길 때 추가합니다.
- 시작 화면에는 현재처럼 백엔드 연결 상태를 표시합니다. 연결 성공은 업무 API 권한이나 DB 정상 상태를 보장한다는 의미로 표현하지 않습니다.
- 로그인 화면은 F2에서 별도 배치로 연결하며 F1에 가짜 로그인 폼을 만들지 않습니다.

### 2. 화면 크기와 스크롤 기본안

| 조건 | 배치 |
|---|---|
| 너비 1024px 이상 | 높이 56px 헤더, 너비 224px 탐색 영역, 나머지 본문. 본문 여백 24px |
| 너비 1024px 미만 | 헤더 아래 가로 탐색 영역, 그 아래 본문. 본문 여백 16px |
| 너비 320px 이상 | 제목·행동 영역 줄바꿈 허용, 입력과 상태 문구는 컨테이너 안에 표시 |

기본 화면은 문서 전체의 세로 스크롤을 사용하고 중첩 세로 스크롤을 만들지 않습니다. 표·이미지 작업 영역에 필요한 별도 스크롤은 해당 기능에서 설계합니다. F1은 320px·768px·1280px 너비와 200% 확대에서 내용 가림과 불필요한 화면 전체 가로 스크롤을 확인합니다. 이미지 편집 기능의 작은 화면 지원 수준은 이 조건만으로 확정하지 않습니다.

### 3. 화면 이동과 URL 기본안

| 경로 | 용도 | 적용 단계 |
|---|---|---|
| `/` | 현재 시작 화면과 연결 상태 | F1 |
| 일치하지 않는 경로 | 찾을 수 없는 화면과 시작 위치 링크 | F1 |
| `/login` | 로그인 | F2 |
| `/datasets` | 데이터셋 목록 | F3 |
| `/datasets/:datasetId` | 데이터셋 상세 | F3 |

위 경로는 브라우저 화면 주소 초안이며 서버 API 계약이 아닙니다. 이미지 상세·수집·작업 화면의 경로는 데이터 관계와 화면 구성이 확정되면 추가합니다.

- 화면 이동은 실제 링크를 사용해 새 탭 열기와 주소 복사를 지원하는 방향입니다. 브라우저 뒤로·앞으로 이동, 직접 접근, 새로고침 후 같은 화면 복원을 완료 기준으로 둡니다.
- 알 수 없는 경로를 시작 화면으로 조용히 바꾸지 않고 찾을 수 없는 화면을 보여줍니다. 이는 클라이언트 표시이며 HTTP 404 상태 반환까지 보장하지 않습니다.
- 이동 후 문서 제목과 본문 제목을 현재 화면에 맞게 바꾸고 키보드 포커스가 본문 시작을 찾을 수 있게 합니다. 이전 화면의 로딩·오류 상태가 다음 화면에 남지 않게 합니다.
- History 기반 경로와 hash 기반 경로, 라우터 도입 여부는 미결정입니다. History 방식을 채택하면 정적 호스팅의 SPA fallback이 필요하며 `/api`와 정적 파일 요청은 해당 fallback과 구분해야 합니다.
- 라우터를 쓰지 않는 경우 직접 구현할 이동 처리 범위와 코드를 먼저 비교합니다. 단순함을 이유로 별도 범용 라우팅 프레임워크를 만들지 않습니다.

### 4. 시각 스타일 기본안

- 기존 어두운 배경과 밝은 글자 톤을 이어갑니다. 확정된 브랜드 색상이나 외부 폰트 도입은 없습니다.
- `style.css`의 CSS 사용자 정의 속성으로 배경, 표면, 본문·보조 글자, 경계, 강조, 성공·실패, 포커스 색상과 반복 간격을 정의합니다. 실제 사용되는 값만 둡니다.
- 간격은 4·8·12·16·24·32px, 기본 글자 16px, 보조 글자 14px, 화면 제목 24~32px를 기본안으로 합니다.
- 링크는 이동, 버튼은 행동에 사용합니다. 포커스 윤곽을 제거하지 않으며 hover·focus·disabled 상태를 구분합니다.
- 상태는 색과 함께 설명 문구를 사용합니다. 기본·hover·focus 상태의 글자 대비를 확인하고 작은 글자는 4.5:1 이상을 목표로 합니다.
- 공통 스타일은 레이아웃·기본 요소에 한정합니다. 특정 업무 화면 스타일은 해당 기능이 추가될 때 둡니다.

### 5. 화면 상태 표시

| 상태 | 화면 표시 | 사용자 행동 |
|---|---|---|
| 로딩 | 현재 조회 중인 내용을 텍스트로 안내, 필요 시 `role="status"` | 조회 중 동일 요청의 반복 실행 제한 |
| 정상 | 실제 응답으로 확인한 내용 | 해당 화면의 다음 행동 |
| 빈 결과 | 조회는 성공했으나 항목이 없음을 안내 | 기능·권한에 맞는 등록 또는 조건 변경. F3 이후 적용 |
| 실패 | 연결·조회에 실패했다는 안내, 내부 예외 원문 숨김 | 읽기 요청을 다시 확인하는 행동 |
| 찾을 수 없음 | 현재 화면 주소를 찾을 수 없다는 안내 | 시작 위치 링크 |

F1에서 구현할 조회 상태는 헬스체크에 한정합니다. 화면 골격은 상태가 바뀌어도 유지합니다. 다시 확인은 사용자가 실행하는 단일 읽기 요청이며 무한 자동 재시도나 주기 조회를 추가하지 않습니다. 오류 안내는 사용자 행동 뒤 발생한 변화가 보조 기술에 전달되도록 하고, 자동으로 사라지는 알림에만 의존하지 않습니다.

### 6. 코드 구성 기본안

```text
frontend/src/
  main.tsx                 # 기존 React 진입점
  App.tsx                  # 화면 연결과 최상위 조합
  layout/
    AppLayout.tsx          # 실제 업무 화면에서 사용하는 헤더·탐색·본문
  pages/
    HomePage.tsx           # 기존 시작 화면과 연결 상태
    NotFoundPage.tsx       # 찾을 수 없는 화면
  api/
    health.ts              # 기존 헬스체크 호출·응답 타입
  style.css                # 최소 스타일 값과 화면 골격
```

- 파일 구분은 책임을 설명하는 초안입니다. 한 곳에서만 쓰는 짧은 헤더·탐색·상태 문구를 추가 파일로 각각 분리하지 않습니다.
- `HomePage`가 헬스체크 상태를 소유합니다. 레이아웃은 HTTP를 호출하지 않고 본문과 탐색을 표시합니다.
- 페이지 조회의 응답·오류는 해당 페이지에서 관리합니다. F1에 전역 상태 저장소나 범용 요청 훅을 도입하지 않습니다.
- 응답 처리와 HTTP 상태 확인은 기존 `api/health.ts` 경계에 둡니다. 토큰이나 모든 API에 대한 오류 변환 계층을 미리 추가하지 않습니다.
- 라우터 선택에 필요한 파일·의존성은 선택 이후 이 구조에 반영합니다. 빈 디렉터리나 미래 업무 페이지는 생성하지 않습니다.

## 데이터·API·권한·오류 처리

- F1은 `GET /api/health`와 현재 `HealthStatus`만 사용합니다. 신규 API나 요청·응답 타입을 만들지 않습니다.
- 공개 헬스체크에 인증 토큰을 보내지 않습니다. 권한별 메뉴, 로그인 복귀 주소와 세션 만료는 F2에서 설계합니다.
- 네트워크 오류·비정상 HTTP 응답은 연결 실패로 표시합니다. 오류 메시지에는 요청 헤더·토큰·서버 예외를 포함하지 않습니다.
- 화면 이탈 후 늦은 응답이 다른 화면의 상태를 바꾸지 않도록 페이지의 요청 수명과 상태 갱신 범위를 맞춥니다.
- 로컬 포트·프록시·빌드 동작은 기존 설정을 유지합니다. 서버 외부 설정이나 배포 절차 변경은 이번 문서 작성 범위에 없습니다.

## 미결정 질문과 후속 조치

1. 시작 화면을 F1의 진입 화면으로 유지할지, F2부터 로그인·데이터셋으로 연결하는 진입 정책을 확정합니다.
2. 업무 화면 배치·좁은 화면 탐색 방식·어두운 스타일 기본안을 검토합니다.
3. 화면 주소 형식과 라우터 필요성을 결정합니다. 신규 의존성을 제안하면 목적·추가 코드 범위·필요성을 제시하고 승인 후 반영합니다.
4. 기능 자동 검증에 사용할 기존 수단을 확인하고 신규 테스트 도구가 필요하면 도입 승인을 받습니다. 전용 검증 프레임워크는 만들지 않습니다.
