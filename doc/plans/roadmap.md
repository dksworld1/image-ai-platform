# 개발 계획

상태: 제품 단계 설계 중
갱신일: 2026-11-07

## 현재 기준선

- React + TypeScript + Vite 프런트엔드 골격
- Spring Boot REST API 및 헬스체크
- 개발 프록시와 CORS 기본 설정
- 제품 개요와 단계별 기능 설계 문서

위 항목 중 마지막 항목은 문서화 상태를 말하며 제품 기능 구현 완료를 뜻하지 않습니다.

## 최우선 백엔드 개발 항목

- [애플리케이션 설정 모듈](../stages/stage-application-settings.md) 개발을 다음 백엔드 작업의 최우선 순위로 진행합니다.
- 런타임 설정의 properties 자동 탐색·중앙 로더·불변 객체·클래스 초기화 기반 정적 접근을 구현했습니다. [ADR-014](../decisions/ADR-014-static-runtime-settings.md)를 따르며 실제 설정 항목이 정해지면 필드·매핑을 추가합니다.
- 아래 기존 단계 번호는 유지하며, 남은 인증·권한 및 제품 기능 개발보다 설정 모듈을 먼저 진행합니다.

## 제안 구현 순서

단계별 목표·개념·결정·완료 조건은 [기능 구현 단계](../stages/README.md)에서 관리합니다.

1. 백엔드 프레임워크와 데이터 기반
2. 인증과 권한
3. 데이터셋과 메타데이터
4. 이미지 수집과 업로드
5. 전처리
6. 레이블링
7. 클러스터링
8. 사용자 플러그인 이미지 처리

## 후속 설계 우선 항목

- 사용자와 대표 작업 흐름 구체화
- 이미지 저장소, 업로드 제한, 보존·삭제 정책
- 장시간 작업의 상태·실패·재시도 모델
- 레이블 체계와 검수 흐름
- 플러그인 신뢰 경계와 격리 방식
- 운영 배포, 관측성, 비용 및 보안 요구사항

## DB 마이그레이션 현재 상태

local/test에서 app·audit 데이터소스별 Flyway를 실행합니다. 다중 SQL 위치, 테스트 seed와 빈 목록의 적용 건너뛰기를 구현했습니다. dev/prod는 기본 비활성화이며 외부 YAML로 설정합니다. [설정 방법과 검증 기록](../operations/database-migration.md)을 참고합니다.
