## 문제와 목표

데이터셋과 앞 단계 산출물을 파이썬 코드에 전달하고, 학습 모델이나 평가 결과 등 여러 산출물을 한 번의 실행에서 만들어 다음 스테이지에 연결합니다. 모델 한 건은 가중치·설정·토크나이저 등을 함께 보관하는 아티팩트 한 건으로 표현합니다.

## 범위와 제외 범위

1차 개발 범위는 파이썬 스크립트 실행, 입력 파일 준비, 결과 수집과 아티팩트 확정입니다. 모델 레지스트리, 모델 배포, 다른 실행 유형, 사용자 임의 코드 업로드 및 분산 워커는 후속 범위입니다.

## 제안 설계

### 스테이지 타입과 버전

스테이지 버전 생성 시 실행 타입을 지정합니다. 1차 지원 값은 `PYTHON_SCRIPT`입니다. 전처리·학습·평가 스테이지가 같은 실행 타입을 사용하고 각 버전의 스크립트와 포트로 처리 목적을 표현합니다.

스테이지 버전에는 실행 타입, 스크립트 배포물의 고정 식별값, 상대 진입점, 파이썬 실행 환경 식별값, 입출력 계약 버전, 포트 선언 및 매개변수 기본값을 기록합니다. 실행 환경에는 파이썬과 의존성 버전이 포함됩니다. 공개된 버전은 고정하며 변경 시 새 버전을 발행합니다. 파이프라인 노드는 실행할 스테이지 버전을 명시적으로 참조합니다.

### 입력과 출력

| 실행 요청에 바인딩하는 입력 | 실행에 전달하는 값 |
|---|---|
| 데이터셋 | 저장된 불변 데이터셋 ID를 선택합니다. 실행은 해당 스냅샷 아티팩트 ID를 사용합니다. [불변 데이터셋과 파생 저장 설계](dataset-version-design.md) |
| 기존 아티팩트 | 같은 공간에서 실행 요청자가 읽을 수 있는 `AVAILABLE` 아티팩트 ID를 고정합니다. |
| 내부 학습 모델 | 앞 단계의 성공 시도에서 확정한 모델 아티팩트 ID를 연결하거나 이전에 확정된 모델 아티팩트를 선택합니다. |

데이터셋 스냅샷은 데이터셋 저장 시 준비합니다. 실행과 재시도에서는 처음 선택한 아티팩트 ID를 사용합니다. 백엔드는 데이터셋 매니페스트를 해석해 상속한 파일까지 읽기 전용 입력으로 준비합니다.

기존 파이프라인 설계대로 이름 있는 포트 하나에 아티팩트 하나를 연결합니다. 서로 독립적인 여러 결과는 출력 포트를 여럿 선언해 전달합니다. 예를 들어 학습 스테이지의 `trained_model` 포트는 모델 아티팩트를, `metrics` 포트는 평가 지표 아티팩트를 제공합니다. 모델 아티팩트 하나에는 여러 파일을 포함할 수 있습니다. 1차에는 선언한 출력 포트마다 결과 한 건을 요구합니다. 선택 입력은 생략할 수 있으며 필수 입력, 포트별 데이터 종류, 선언된 스키마를 실행 전에 확인합니다.

### 파이썬 실행 계약

1. 백엔드는 시도별 작업 디렉터리를 만들고, 확정 입력 파일을 읽기 전용으로 제공하고 출력 디렉터리를 준비합니다.
2. 백엔드는 고정된 파이썬 실행 파일로 진입점을 자식 프로세스에서 실행합니다. 인자로 `--request <경로>`와 `--result <경로>`를 전달합니다. 요청 파일은 UTF-8 JSON이며 `contractVersion`, `parameters`, 포트 이름별 `inputs`와 `outputs`를 담습니다. 각 입력에는 아티팩트 ID, 데이터 종류, 작업 디렉터리 기준 상대 파일 경로를 담고, 각 출력에는 상대 출력 디렉터리를 담습니다. 값이 없는 선택 입력은 생략합니다.
3. 스크립트는 포트별 출력 디렉터리에 파일을 작성하고, UTF-8 JSON 결과 파일의 `outputs`에 포트 이름별 상대 파일 경로 목록을 씁니다. 정상 완료 시 종료 코드 `0`을 반환합니다. 표준 출력과 표준 오류는 시도별 로그로 수집합니다.
4. 백엔드는 종료 코드, 결과 JSON, 포트 일치 여부, 상대 경로 범위, 파일 존재 및 선언된 제약을 확인합니다. 데이터 종류는 포트 선언을 기준으로 등록하고 실제 형식과 스키마는 처리 계약에 따라 검증합니다. 백엔드 프로세스의 `ArtifactService`가 파일을 등록하고 확정합니다.
5. 모든 출력이 확정된 뒤 출력 바인딩과 채택 시도를 함께 기록해 후속 노드에서 조회할 수 있게 합니다. 스크립트 실패, 시간 초과, 취소, 계약 위반 또는 일부 등록 실패 시 해당 시도의 출력을 전달하지 않고 오류 원인을 기록합니다. 시도의 미채택 산출물은 아티팩트 생명주기에 따라 정리합니다. 재시도는 같은 입력과 스테이지 버전을 사용하고 작업 경로를 새로 만듭니다.

## 대안과 장단점

- 자식 프로세스와 JSON 파일 계약은 기존 백엔드의 아티팩트 생명주기를 재사용할 수 있고 계약을 독립적으로 검증하기 쉽습니다. 입력 파일 준비와 자식 프로세스 종료 처리가 필요합니다.
- 원격 파이썬 워커는 실행 자원을 독립적으로 운영할 수 있습니다. 작업 전달, 파일 전송, 결과 채택을 위한 프로세스 간 계약이 필요하므로 1차는 로컬 자식 프로세스로 시작합니다.

## 보안·운영

1차는 운영자가 등록한 버전 고정 스크립트만 실행합니다. 백엔드가 실행 요청자의 기능 권한과 공간 멤버십을 검사하고 스크립트에는 작업에 필요한 파일과 매개변수만 전달합니다. 스크립트에는 DB 접속 정보나 서비스 자격 증명을 전달하지 않습니다. 자식 프로세스 경계만으로 파일·네트워크 접근이 격리되지는 않습니다. 사용자 제공 코드를 지원하기 전에 별도 격리 방식을 결정합니다.

실행 시도별로 시간 한도를 적용하고 취소·시간 초과 시 자식 프로세스 트리를 종료합니다. 로그는 크기를 제한하고 시도 ID로 조회합니다. 구체적인 런타임 배치와 자원 한도 값은 구현 설계에서 확정합니다.

## 구현 및 검증 계획

1. 스테이지 버전에 `PYTHON_SCRIPT`와 진입점, 실행 환경, 계약 버전을 등록하고 해당 버전을 실행에 고정합니다.
2. 데이터셋 스냅샷과 기존 모델 아티팩트를 각각 입력받아 새 모델과 지표를 생성한 뒤, 후속 스테이지가 새 모델을 읽는 흐름을 검증합니다.
3. 필수 입력 누락, 잘못된 결과 경로, 시간 초과와 일부 출력 등록 실패에서 후속 전달이 차단되는지 검증합니다. 재시도 시 입력 ID가 유지되고 새 시도의 성공 결과만 연결되는지 확인합니다.

## 결정 및 결과

1차 실행 방식과 모델의 아티팩트 포함 관계는 요청 기준입니다. 구체적인 타입 식별자, 데이터셋 스냅샷 변환, JSON 계약과 실행 범위는 승인 검토 대상입니다. 채택 시 ADR과 구현 결과를 연결합니다.
