# 불변 데이터셋과 파생 저장 설계

- 종류: 설계 제안
- 상태: 불변·상속 정책 결정, 세부 구현 검토 중
- 구현 상태: 미구현
- 갱신일: 2026-11-22
- 관련 결정: [ADR-052](../../decisions/ADR-052-immutable-derived-datasets.md)
- 관련 문서: [데이터셋 단계](stage-03-datasets.md), [파이썬 플러그인 스테이지 설계](python-plugin-stage-design.md)

## 문제와 목표

저장한 데이터셋의 메타데이터와 파일 구성을 고정하고, 기존 구성을 바꾸려면 파생 데이터셋을 새로 저장합니다. 저장된 데이터셋 ID 하나로 학습에 사용한 입력을 재현하고, 부모 ID로 파생 경로를 추적할 수 있어야 합니다.

## 범위와 제외 범위

1차는 최초 저장, 부모에서 파생 저장, 구성·부모 조회, 스테이지 입력 연동을 다룹니다. 여러 부모 병합, 작업본 공동 편집, 저장된 데이터셋의 물리 삭제와 공유 파일 수거는 후속 범위입니다.

## 제안 설계

### 사용자 흐름

1. 최초 데이터셋은 빈 작업본에서 시작합니다. 파생할 때에는 사용자가 기존 데이터셋을 선택하고 이름·설명·파일 목록을 작업본에 불러옵니다.
2. 작업본에서 이미지와 데이터 파일을 추가·교체·제외하고 이름과 설명을 바꿀 수 있습니다. 변경은 작업본에만 적용되며 취소하면 저장된 데이터셋에 반영되지 않습니다.
3. 저장하면 서버가 새 `dataset_id`를 발급하고 직접 상속한 `parent_dataset_id`를 기록합니다. 최초 저장의 부모 ID는 NULL입니다. 부모와 같은 공간에 저장하며, 같은 부모에서 여러 자식을 만들 수 있습니다. 새 데이터셋은 저장 즉시 확정됩니다.
4. 저장 후에는 이름·설명·부모 ID·구성과 파일 내용에 대한 직접 변경을 서버에서 거부합니다. 조회는 저장된 ID를 기준으로 하며 부모를 새 자식으로 자동 치환하지 않습니다.

예를 들어 부모 `D1`에 이미지 A와 CSV B가 있고, A를 교체하고 B를 제외한 뒤 C를 추가해 저장하면 `D2`가 생깁니다. `D2.parent_dataset_id`는 `D1`입니다. `D2`에는 새 A와 C가 있고 `D1`에는 기존 A와 B가 남습니다.

### 데이터 모델과 변경분 저장

| 구성 | 제안 계약 |
|---|---|
| `dataset` | 기존 ID와 공간을 사용합니다. `parent_dataset_id`는 같은 공간의 기존 데이터셋을 참조하는 선택 FK입니다. `snapshot_artifact_id`는 확정 아티팩트를 참조하며 데이터셋마다 고유합니다. 부모 FK에 연쇄 삭제를 적용하지 않습니다. |
| 데이터셋 스냅샷 아티팩트 | 해당 데이터셋의 전체 구성 목록을 담은 매니페스트와 이번 저장에서 새로 추가하거나 교체한 파일을 보관합니다. |
| 매니페스트 항목 | 파일 종류, 논리 상대 경로, 본문을 보관한 아티팩트 ID와 파일 ID를 기록합니다. 이미지와 데이터 파일은 종류별 경로로 구분합니다. |

변경이 없는 파일은 부모 매니페스트의 본문 참조를 그대로 사용합니다. 파일을 제외하면 자식 매니페스트에서 그 참조를 뺍니다. 이름이나 논리 경로만 바꾸는 작업은 파일 본문을 재사용합니다. 자식에 남은 모든 파일 참조를 매니페스트에 기록하므로, 조회와 스테이지 실행은 조상별 변경 내역을 재생할 필요가 없습니다. 파일 실체와 체크섬은 최초로 본문을 저장한 아티팩트에서 관리합니다. 공통 감사 컬럼과 내부 사용자 키 규칙은 기존 스키마 기준을 따릅니다.

### 저장과 실행 경계

- 저장 요청은 부모 ID, 작업본 메타데이터, 구성 변경과 새 파일을 전달합니다. 서버는 부모 조회 및 같은 공간의 생성 권한을 확인하고, 상속할 파일을 부모의 확정 구성에서 해석합니다. 클라이언트가 지정한 임의 아티팩트나 경로는 상속 대상으로 받지 않습니다.
- 새 파일과 매니페스트를 기록하고 아티팩트를 확정한 뒤 데이터셋을 같은 app DB 트랜잭션에서 공개합니다. 실패하면 신규 데이터셋을 공개하지 않고 해당 저장에서 만든 파일을 롤백 처리합니다. 부모와 다른 자식의 상태는 고정되어 있으므로 동시 파생은 별도의 ID로 저장할 수 있습니다.
- 스테이지 실행은 저장된 데이터셋 ID를 선택하고 해당 스냅샷 아티팩트 ID를 고정합니다. 백엔드는 매니페스트가 가리키는 확정 파일을 작업 디렉터리에 준비합니다. 이 해석은 데이터셋 스냅샷에 적용하며 기존 모델·일반 아티팩트의 파일 계약은 유지합니다. 재시도에도 같은 ID와 구성을 사용합니다.

### 기존 데이터셋 전환과 보존

기존 데이터셋은 전환 시점의 활성 이미지·데이터 파일을 최초 매니페스트로 확정하고, 기존 데이터셋 ID와 공간 귀속을 유지합니다. 부모는 NULL로 두며 현재 파일 이력은 과거 작업의 조회 근거로 보존합니다. 모든 기존 데이터셋의 스냅샷 준비와 검증을 끝낸 뒤 직접 수정·파일 변경 API를 차단합니다. 전환 중 구성이 바뀌지 않도록 적용 창의 쓰기 정책과 재실행 절차는 구현 설계에서 확정합니다.

1차는 저장된 데이터셋의 삭제와 스냅샷 실체 삭제를 제한합니다. 자식이 참조하는 파일은 부모 또는 조상의 아티팩트에 있을 수 있으므로 보관 만료만으로 수거하지 않습니다.

## 대안과 장단점

- **전체 목록과 변경 파일 저장**은 파일 복사를 줄이고 개별 데이터셋의 구성을 바로 해석할 수 있습니다. 자식이 참조하는 공유 파일의 보존이 필요합니다.
- **변경 내역만 저장**은 목록 크기도 줄일 수 있습니다. 실행 시 조상 순서대로 변경을 적용해야 하고, 참조가 깊어질수록 조회와 보존 처리가 복잡해집니다.

## 보안·운영

파생 저장과 실행에 기존 공간 멤버십 및 기능 권한을 적용합니다. 매니페스트에는 논리 경로와 식별자만 기록하고 실제 저장 위치는 백엔드에서 해석합니다. 본문 참조가 누락되었거나 소속이 일치하지 않으면 저장 또는 실행 준비를 실패 처리합니다.

## 구현 및 검증 계획

1. 기존 데이터셋 전환 후 동일한 ID로 기존 활성 구성을 조회할 수 있고, 저장된 메타데이터·파일을 기존 변경 경로에서도 변경할 수 없는지 확인합니다.
2. 추가·교체·제외 후 저장한 데이터셋에 새 ID와 정확한 부모 ID가 기록되는지 확인합니다. 부모의 파일 목록과 체크섬이 그대로이고, 상속 파일이 복사되지 않는지 확인합니다.
3. 같은 부모에서 두 자식을 독립적으로 저장하고, 저장 실패나 취소가 부모와 다른 자식에 영향을 주지 않는지 확인합니다.
4. 조상 파일을 공유하는 데이터셋의 스테이지 입력 준비와 재시도를 검증합니다.

## 결정 및 결과

불변 저장과 부모 ID를 통한 상속은 ADR-052에 기록했습니다. 매니페스트 구조, 기존 데이터셋 전환 절차와 물리 삭제 제한은 1차 세부 제안입니다.
