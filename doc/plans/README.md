## 관리 원칙

- 로드맵은 전체 순서, 작업계획은 실행 단위, 설계 제안은 검토할 대안과 선택 근거를 기록합니다. 같은 업무의 계획과 설계는 한 문서에 함께 작성할 수 있으며 별도 파일이 필요하면 서로 연결하고 내용을 중복 작성하지 않습니다.
- 각 문서에 종류·상태·작성일 또는 갱신일을 기록합니다. 부분 채택된 제안은 채택·미정·대체된 내용을 구분하고, 작업별 상태는 해당 작업 목록에서 관리합니다.
- 단계 문서는 `front/`와 `backend/`에서 관리하고 실제 검증과 완료 근거를 기록합니다. 현재 구현 계약은 아키텍처·API·테이블 정의서, 중요한 채택 결정은 ADR에 연결합니다. 이 폴더에 있다는 이유로 미정 사항을 현재 구현으로 다루지 않습니다.
- 설계 제안 작성 시 [설계 제안 서식](../templates/design-proposal.md)을 사용합니다. 문서 승인·구현·취소·대체 시 상태와 결과 링크를 갱신합니다.

## 통합 이력

2026-11-10: 전체 문서를 점검해 계획·제안·단계별 설계·진척 관리를 `plans/`로 통합했습니다. 기존 로드맵과 현황판은 아래에 합치고 원래 기준일·검증 기록을 유지합니다. 현재 데이터셋 지시 단위는 [작업계획서](dataset-development-plan.md)에서 확인합니다. 문서 통합만으로 업무 상태나 미정 정책을 변경하지 않습니다.
