# ADR-043: 데이터셋 관리의 이미지·데이터 파일 분리

- 상태: 채택
- 날짜: 2026-11-13
- 대체/관련 기록: ADR-039·040·041·042 확장

후속 결정: [ADR-044](ADR-044-data-file-binary-upload.md)가 아래 이미지 제외 방침을 대체합니다. 현재 데이터 파일은 이미지를 포함한 모든 형식의 원본 바이너리이며 썸네일을 관리하지 않습니다. 나머지 탭·권한·저장 구조는 유지합니다.

## 맥락

데이터셋은 이미지뿐 아니라 텍스트·바이너리 분석 대상도 포함할 수 있습니다. 사용자는 이미지 관리 화면을 데이터셋 관리로 바꾸고 두 종류의 업로드를 별도 탭으로 제공하도록 승인했습니다.

## 대안

- 이미지 테이블과 권한에 모든 파일을 통합: 썸네일·이미지 형식 제약과 데이터 파일 관리가 결합됩니다.
- 독립 파일 모델과 권한, 같은 관리 페이지의 두 탭: 기존 이미지 동작을 보존하며 유형별 조건을 관리할 수 있습니다.

## 결정

두 번째 방식을 채택합니다. dataset_file과 dataset_file_history, 별도 로컬 저장 루트와 dataset:file:read/upload/update/delete를 사용합니다. 공통 seed는 권한 카탈로그만, local seed는 admin 역할 부여만 담당합니다. 쓰기는 활성 공간 멤버이면서 공간 운영자 또는 데이터셋 생성자여야 합니다.

데이터 파일은 파싱하지 않는 원본 바이너리로 저장하고 다운로드로 제공합니다. 감지된 이미지는 이미지 탭으로 안내하되 모든 이미지 형식을 완전히 식별한다고 보장하지 않습니다. 동명 중복·명시적 교체·버전·이력·설명 일괄 수정·논리 삭제는 이미지 관리의 기존 원칙을 적용합니다.

## 결과

화면의 목록·업로드 조작은 기존 컴포넌트와 작은 타입 변환으로 함께 사용합니다. 이미지·데이터 파일의 테이블과 서버 업무 로직은 분리합니다. 기존 이미지 API·데이터와 과거 경로는 보존합니다. 내용 분석·미리보기·물리 삭제는 후속 범위입니다. 실제 계약은 [API](../api/api.md#데이터-파일-api--2026-11-13), 데이터 구조는 [파일 정의](../db-schema/tables/dataset/dataset-file.md), 설정은 [배포](../operations/deployment.md#데이터-파일-저장-설정--2026-11-13)를 따릅니다.
