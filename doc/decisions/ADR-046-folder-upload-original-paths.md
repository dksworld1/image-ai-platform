# ADR-046: 폴더 업로드와 원본 상대 경로 보존

- 상태: 채택
- 날짜: 2026-11-13
- 대체/관련 기록: ADR-039·043·044·045 확장

## 맥락

사용자는 이미지·데이터 파일 모두 폴더 업로드를 지원하고 선택한 폴더부터 시작하는 경로를 원본 파일명에 저장하도록 요청했습니다.

## 대안

- 별도 폴더 모델·탐색 트리: 현재 요청보다 큰 업무 모델이 필요합니다.
- 원본 파일명에 상대 경로 보존: 기존 목록·중복·버전 관리 구조로 폴더 출처를 구분할 수 있습니다.

## 결정

두 탭의 일반·수정 업로드에 브라우저 폴더 선택을 추가합니다. webkitRelativePath를 multipart relativePath 필드로 전송하고 original_filename에 선택한 최상위 폴더를 포함해 저장합니다. 구분자는 /로 통일합니다. 전체 최대 1,024자, 각 경로 요소 최대 255자이며 절대 경로·상위 이동·빈 요소·제어 문자는 거부합니다.

같은 데이터셋·같은 파일 유형에서 전체 상대 경로를 중복·교체 기준으로 사용합니다. 다른 하위 폴더의 같은 이름은 별개 파일입니다. relativePath가 없는 기존 클라이언트는 기존처럼 파일명만 저장합니다. 빈 폴더는 파일이 없으므로 저장하지 않습니다.

## 결과

V25에서 두 파일 테이블의 original_filename·active_filename과 두 이력의 original_filename을 VARCHAR(1024)로 확장합니다. 실제 디스크 폴더를 재현하지 않고 기존 UUID 저장 구조와 유형별 썸네일 정책을 유지합니다. 개별 다운로드명은 마지막 파일명이며 전체 상대 경로는 목록·응답·이력에서 보존합니다. 기존 파일의 경로를 추정해 이관하지 않습니다. 폴더 선택 후 파일별 순차 전송·성공/실패 처리는 기존 흐름을 유지하며 폴더 전체를 하나의 트랜잭션으로 묶지 않습니다.
