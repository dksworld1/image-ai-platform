# ADR-053: 과거 데이터셋 버전으로 현재 편집본 준비

- 상태: 채택·구현
- 날짜: 2026-11-23
- 관련 결정: [ADR-052](ADR-052-dataset-version-snapshots.md)

## 맥락

사용자가 v5 구성으로 편집본을 준비하고 필요한 파일을 수정한 뒤 다음 번호의 버전(v9까지 있다면 v10)을 만드는 흐름을 요청했습니다. 확정 버전은 불변이며 파일 바이트를 다시 복사할 필요는 없습니다. 전체 목록 스냅샷이므로 새 버전의 복원에 base_version_id도 필요하지 않습니다.

## 대안

- 파일을 복사해 새 파일 버전 행을 생성: 추가 저장 공간이 필요하며 기존 경로 고유 제약을 바꾸거나 새 복제 구조를 도입해야 합니다.
- 이미 보존된 파일 버전 행을 현재 목록에 다시 포함: 바이트·경로·파일 ID를 재사용하고 기존 스냅샷은 그대로 유지할 수 있습니다.

## 결정

선택한 버전과 같은 데이터셋의 공유된 현재 편집본 전체를 교체합니다. 같은 dataset 행 잠금 안에서 기준 버전·멤버십·관리 범위를 검증하고 기준 실파일의 존재·읽기 가능·크기를 확인합니다. 현재 활성 이미지·데이터 파일은 논리 삭제하고 기준 구성의 파일 ID를 다시 활성화하며 당시 원본 이름·설명·형식·크기를 적용합니다. 데이터셋 이름·설명도 당시 값으로 적용합니다. 저장 경로·바이트·썸네일·원본 파일 생성 정보는 재사용합니다.

현재 목록 제외는 DELETE, 기준 파일의 재포함은 UPDATE로 기존 파일 작업 이력에 기록합니다. 목록·설명·이력 갱신은 한 app 트랜잭션이며 실패 시 전부 롤백합니다. 확정 dataset_version과 구성 항목은 변경하지 않습니다.

기능 권한 dataset:version:restore와 dataset:version:read, 기존 데이터셋 관리 범위 및 활성 멤버십을 모두 요구합니다. 개별 이미지·파일 편집 권한만으로 전체 편집본 교체를 허용하지 않습니다. local admin에만 신규 권한을 자동 연결합니다.

## 결과

적용은 새 데이터셋 버전을 생성하지 않습니다. 파일을 편집한 후 기존 버전 생성 기능으로 최대 번호+1을 발급합니다. 개인별 독립 브랜치나 base_version_id 컬럼·참조는 추가하지 않습니다. 새 스키마 DDL은 없습니다.

개별 파일 ID·버전 번호는 기준 버전의 값을 재사용합니다. 이후 수정 업로드는 그 파일에서 새 UUID·다음 개별 번호로 갈라지므로 과거 다른 분기에 같은 개별 번호가 존재할 수 있습니다. 파일의 정확한 식별은 UUID이며 데이터셋 전체 버전 번호는 계속 증가합니다. 단순 파일명이나 개별 번호만으로 계보를 추정하지 않습니다.

공유 편집본에 대한 교체이므로 화면에서 적용 범위·미확정 변경의 목록 제외를 확인받습니다. 현재 편집본을 별도로 보존하려면 적용 전에 사용자가 버전을 생성해야 하며, 자동 체크포인트 버전은 만들지 않습니다. 통신 결과가 불명확하면 자동 재시도하지 않고 현재 파일 목록을 확인합니다.
