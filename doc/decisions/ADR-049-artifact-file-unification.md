# ADR-049: 아티팩트와 다중 파일 모델로 통합

- 상태: 채택
- 날짜: 2026-11-21
- 관련 결정: [ADR-047](ADR-047-artifacts-and-versioned-sets.md)의 셋 모델을 대체, [ADR-048](ADR-048-local-file-storage-module.md)

## 맥락

아티팩트 하나가 고정 버전의 데이터 단위이며 여러 파일을 포함할 수 있습니다. 사용자는 별도 셋 개념을 아티팩트에 통합하도록 결정했습니다.

## 대안

- 별도 셋과 버전을 유지하면 독립적인 아티팩트 묶음을 표현할 수 있지만 두 가지 데이터 단위를 운영해야 합니다.
- 고정 아티팩트를 직접 참조하면 파일 구성과 데이터 식별을 하나의 단위로 유지할 수 있습니다.

## 결정

활성 모델은 artifact와 artifact_file입니다. 작성 상태에서 파일을 추가하고 확정되면 파일 구성이 고정됩니다. 파이프라인 포트 설계에서 실제 입출력은 확정 아티팩트 ID를 참조합니다.

## 결과

셋 API와 백엔드 매핑을 제거하고 신규 권한 시드에서는 아티팩트 권한만 등록합니다. 적용된 V26과 기존 셋·권한 데이터는 보존합니다. 기존 셋의 구성·순서·대응 키를 새 파일 구성으로 이관하는 작업은 별도 결정이 필요합니다. [폐기 이력](../archive/artifact-set/README.md)
