# ADR-047: 아티팩트와 버전 기반 아티팩트셋

- 상태: 부분 대체 — 셋 모델은 [ADR-049](ADR-049-artifact-file-unification.md)로 폐기
- 날짜: 2026-11-20
- 관련 기록: ADR-037, [실행 파이프라인 설계](../plans/execution-pipeline-data-modeling.md)

## 맥락

사용자가 실행 파이프라인 설계 문서를 기준으로 아티팩트와 아티팩트셋 백엔드 구현을 지시했습니다. 파일 하나와 아티팩트 하나는 같은 개념이 아니며, 실행 입력은 특정 셋 버전으로 고정해야 합니다. 나머지 파이프라인 논리 모델은 제안 상태를 유지합니다.

## 대안

- 파일 하나당 산출물 하나와 실행별 파일셋: 다중 파일 모델과 재사용 가능한 셋 버전을 표현하지 못합니다.
- 아티팩트·파일, 셋·버전·구성의 5개 엔티티: 고정된 내용과 집합 구성을 독립적으로 재사용할 수 있습니다.

## 결정

artifact·artifact_file·artifact_set·artifact_set_version·artifact_set_member를 app DB에 구현합니다. 모든 연결은 같은 워크스페이스 안에서만 허용하고 기능 권한과 활성 공간의 활성 멤버십을 서비스에서 확인합니다. 권한은 pipeline:artifact:create/read/update와 pipeline:artifactset:create/read/update입니다. 관리자 이름으로 우회하지 않습니다. 셋 구성 편집에는 참조할 아티팩트 read도 필요합니다.

아티팩트는 WRITING에서 파일을 등록하고 실제 크기·SHA-256을 다시 검증한 뒤 AVAILABLE로 확정합니다. 완료·실패 처리는 멱등적이며 AVAILABLE은 내용 변경을 금지합니다. 교체는 새 아티팩트로 표현합니다. 자료 종류와 스키마는 사용자 문자열이며 종류 등록부·스키마 실체 검증을 강제하지 않습니다. 스키마 이름·버전은 함께 지정하거나 함께 생략합니다.

셋은 논리 ID와 버전을 분리합니다. 버전은 DRAFT에서 AVAILABLE 아티팩트의 순서·원본 대응 키를 편집하고 CONFIRMED로 확정하면 불변입니다. 새 버전은 비어 있는 초안으로 생성하며 기존 파일을 복사하지 않습니다. 같은 버전에 같은 아티팩트·순서를 중복 등록하지 않습니다. 빈 셋은 허용합니다. 버전 번호 할당은 셋 행 잠금, 구성 편집·확정은 버전 행 잠금으로 직렬화합니다. 구성 체크섬은 정렬된 항목의 SHA-256이며 알고리즘 상세는 API 계약에 둡니다.

현재 파일 저장은 서버가 생성한 UUID 상대 경로와 설정의 루트 키로 분리한 로컬 저장만 제공합니다. NAS·S3 도입은 이 결정에 포함하지 않습니다. DB 롤백 시 신규 파일 삭제를 보상하지만 DB와 파일 저장의 분산 원자성은 보장하지 않습니다.

## 결과

단계·포트·실행 시도·프로비넌스·원본 이관·화면·정리 스케줄러는 구현하지 않습니다. 실행 시도의 토큰과 모든 출력 일괄 채택은 실행 모듈에서 추가해야 합니다. 현재 서비스 메서드는 외부 app 트랜잭션에 참여할 수 있습니다.

보관 기한·보호 여부는 메타데이터로 기록하며, 삭제 정책과 참조 보호의 전체 범위가 미확정이므로 삭제·보호 해제·실체 정리 API는 제공하지 않습니다. 원본 파일 삭제를 수행하지 않아 확정 셋의 입력을 지우는 경로를 만들지 않습니다. deleted_at은 후속 파일 수명주기용 예약 필드입니다.

기준 문서는 [셋 API 및 테이블 이력](../archive/artifact-set/README.md), [테이블](../db-schema/tables/artifact/README.md), [배포](../operations/deployment.md#아티팩트와-파일)를 따릅니다.
