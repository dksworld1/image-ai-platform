# ADR-002: MyBatis와 로컬 테스트용 H2 파일 DB 사용

- 상태: 채택 (스키마 자동 초기화는 [ADR-011](ADR-011-remove-schema-auto-initialization.md)에 따라 제거)
- 날짜: 2026-11-01
- 관련 기록: [1단계 백엔드 프레임워크와 데이터 기반](../plans/backend/stage-01-backend-foundation.md)

## 맥락

백엔드 기능 구현을 시작하기 전에 데이터 소스, SQL 실행 및 트랜잭션 관리의 공통 기반이 필요합니다. 로컬 테스트에서는 별도 DB 서버 의존성 없이 재시작 후에도 데이터 상태를 확인할 수 있는 개발용 구성이 필요합니다.

## 대안

- ORM 중심 접근: SQL 작성량은 줄일 수 있지만 SQL을 명시적으로 관리하려는 요구와 맞지 않을 수 있습니다.
- SQL 매퍼 사용: 쿼리와 매핑을 명시적으로 관리할 수 있으며 매퍼 경계를 설계해야 합니다.
- H2 메모리 모드: 테스트 격리는 쉬우나 프로세스 간 데이터 지속성이 없습니다.
- H2 로컬 파일 모드: 로컬 실행 간 데이터가 유지됩니다. 스키마 변경 이력 및 적용은 별도 관리가 필요합니다.

## 결정

- DB 접근에 SQL 매퍼를 사용하고 프레임워크로 MyBatis를 채택합니다.
- 로컬 테스트 DB로 H2의 파일 저장 모드를 사용합니다.
- 트랜잭션 경계는 업무 단위에 맞춰 서비스 계층에서 관리합니다.
- 로컬 H2 설정을 운영 DB 선택으로 간주하지 않습니다.
- 매퍼 SQL은 XML에 두고 인터페이스는 `classpath*:mapper/**/*.xml` 규칙으로 찾습니다.
- 최초 구현은 테스트 H2 파일에서 누락된 스키마 객체를 자동 생성했으나 현재 동작은 ADR-011로 제거했습니다. app, catalog, archive 테스트 파일 경로는 `config/datasource/jdbc-test.yaml`에서 관리합니다.
- 초기 결정의 환경변수별 연결값 전달 방식은 [ADR-004](ADR-004-datasource-config-files.md)로 대체되었습니다. DB 연결값과 풀 설정은 YAML 파일에서 읽습니다.
- Spring 실행 프로파일은 `prod`, `dev`, `local`로 구분하며 자동화 테스트는 별도 테스트 프로파일을 사용합니다. 테스트 프로파일의 DB는 H2 파일 저장 모드입니다.

## 결과

- SQL과 결과 매핑을 명시적으로 검토할 수 있습니다.
- SQL 실행과 매핑은 MyBatis 매퍼가 담당하고 업무 규칙은 서비스 계층이 담당하도록 경계를 둡니다.
- 파일 기반 H2의 데이터 지속성으로 테스트 간 상태가 유지됩니다. 테스트 데이터 정리 정책은 별도 합의 전까지 기존 데이터를 보존하는 원칙을 따릅니다.
- 운영 DB, SQL 방언 차이 처리 및 XML/어노테이션 선택은 별도 결정이 필요합니다.
- MyBatis SQL 실행과 Spring 트랜잭션의 예외 롤백을 자동 테스트에 포함했습니다.
- `dev`와 `prod`의 실제 데이터소스 값은 환경별 설정으로 공급하며 저장소에 비밀 값을 두지 않습니다. 기본 활성 프로파일과 프로파일별 실행 설정은 구현과 함께 검증합니다.

## 현재 상태 참고

H2 파일 DB 결정은 유지됩니다.
