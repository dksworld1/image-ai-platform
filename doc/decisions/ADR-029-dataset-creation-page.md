# ADR-029: 데이터셋 생성의 독립 페이지와 메뉴 진입

- 상태: 채택
- 날짜: 2026-11-10
- 대체/관련 기록: 데이터셋 스토리보드 v1의 생성 모달 방식을 대체

## 맥락

기존 생성 화면은 이름·설명 입력 모달로 설계했습니다. 사용자가 향후 확장성을 고려해 생성을 별도 화면으로 변경하고 데이터셋 대메뉴 아래 데이터셋 생성 메뉴로 관리하도록 지시했습니다.

## 대안

- 생성 모달: 간단한 입력에 적합하지만 화면 확장과 독립된 진입 흐름에 제약이 있습니다.
- 독립 생성 페이지: 메뉴에서 직접 진입하고 향후 입력 구성을 확장할 공간을 확보할 수 있습니다.

## 결정

데이터셋 생성(DATA-001, DS-CREATE)은 독립 페이지로 구성합니다. 기본 메뉴 경로는 `데이터셋 > 데이터셋 생성`입니다. 기존 목록의 생성 버튼도 동일한 페이지로 연결합니다. 생성 성공 시 새 데이터셋 상세로, 취소 시 저장 없이 데이터셋 목록으로 이동합니다. 실패 시 페이지와 입력값을 유지합니다.

수정·삭제는 기존 모달 방식을 유지하며 전체 화면 구성은 페이지 3개와 모달 2개입니다. 메뉴와 URL은 React 코드에서 관리하며 폐기된 DB 메뉴 모듈을 복원하지 않습니다. 구체 URL과 입력 변경 후 이탈·뒤로가기 처리, 직접 접근·새로고침의 상세 정책은 관련 작업에서 정합니다.

## 결과

2026-11-10 화면 구현: URL은 `/datasets/new`이며 일반 링크와 기존 탭 세션으로 이동합니다. 사용자 지시로 입력 화면까지만 구현했고 실제 저장은 후속 작업입니다. 목록 구현 전까지 취소는 시작 화면(`/`)으로 이동하는 중간 상태입니다. 입력 내용은 화면 이동·새로고침 시 별도 저장하지 않습니다. 목록·저장 구현 후 위 목표 이동 흐름에 맞춥니다.

2026-11-10 추가 확정: 향후 입력 항목 추가를 전제로 세로로 확장되는 폼과 페이지 스크롤을 사용합니다. 필드별 검증·오류와 제출 흐름을 구분하고 명시적 DTO·타입 및 관련 계약을 함께 갱신합니다. 필드 수나 화면 높이를 현재 초안에 고정하지 않으며 범용 동적 폼 프레임워크를 도입하지 않습니다. [작업계획서](../plans/dataset-development-plan.md)의 확장 원칙을 따릅니다.

작업계획의 DS-07을 생성 페이지 구현·연동으로 변경하고 기능 정의·화면 문서에 연결합니다. 스토리보드는 v2로 갱신하고 v1은 과거 설계로 보존합니다. 별도 페이지 선택은 추가 입력 항목이나 기능, 라이브러리·라우터 도입을 확정하는 결정이 아닙니다. 현재는 설계 반영이며 프런트 구현 완료를 의미하지 않습니다.
