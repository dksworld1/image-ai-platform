# ADR-030: 데이터셋 생성 계약과 서버 생성 메타데이터

2026-11-10: 생성자·수정자의 로그인 아이디 기준은 [ADR-031](ADR-031-user-identity-fields.md)의 내부 user_key 기준으로 대체합니다. 기존 메타데이터 값은 이관 후에도 동일한 내부 키로 보존합니다.

- 상태: 채택
- 날짜: 2026-11-10
- 대체/관련 기록: ADR-028, ADR-029

## 맥락

사용자가 생성 백엔드와 고정 컬럼값의 정확한 기록, 생성 날짜·시간의 타임스탬프 관리를 요청했습니다. 공통 생성·수정 컬럼과 화면은 있지만 생성 API·저장소는 없었습니다.

## 대안

- 날짜와 시간을 별도 필드 또는 문자열로 저장: 시점 비교와 시간대 처리가 분산됩니다.
- 시간대 포함 타임스탬프: 공통 규칙을 유지하며 날짜·시간을 하나의 절대 시점으로 저장합니다.

## 결정

POST /api/datasets를 구현하고 app V6에서 dataset 테이블을 생성합니다. 이름은 필수 200자, 설명은 선택 2000자로 제한하고 앞뒤 공백을 제거합니다. 빈 설명은 NULL이며 이름 중복은 허용합니다. UUID 문자열을 서버에서 발급합니다.

생성일시와 수정일시는 UTC OffsetDateTime을 한 번 생성해 마이크로초로 정규화하고 TIMESTAMP(6) WITH TIME ZONE에 동일하게 기록합니다. 생성자·수정자는 SecurityContext의 로그인 아이디로 기록합니다. 요청에 포함된 ID·작업자·감사 시각은 사용하지 않습니다.

이번 생성은 서비스의 @PreAuthorize에서 기존 AuthorizationService.isActiveAccount()로 활성 계정을 확인합니다. 활성 사용자는 별도 역할 없이 생성할 수 있습니다. 소유·공유·향후 관리 권한은 이번 결정으로 확정하지 않으며 생성자는 소유자를 의미하지 않습니다. DAO는 appSqlSessionTemplate, 트랜잭션은 appTransactionManager를 명시합니다.

## 결과

생성 화면에서 실제 저장을 호출하며 요청 중 중복 제출 방지, 실패 시 입력 유지, 성공 시 이름·ID 확인과 폼 초기화를 제공합니다. 상세 화면은 아직 없어 자동 상세 이동은 후속 작업으로 남깁니다. 생성 계약과 입력 타입을 확장할 때 서버·클라이언트·스키마·검증을 함께 갱신합니다. 새로운 의존성이나 범용 프레임워크는 추가하지 않습니다.
