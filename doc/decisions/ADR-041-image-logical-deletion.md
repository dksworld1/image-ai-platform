# ADR-041: 이미지 선택 삭제와 논리 삭제 이력

- 상태: 채택
- 날짜: 2026-11-13
- 대체/관련 기록: ADR-039·040 확장. 개별 이미지 삭제 미구현 상태를 갱신

## 맥락

사용자는 이미지 관리 목록에 행 체크박스와 삭제 버튼을 요청했습니다. 이미지 버전과 실제 파일을 보존하며 생성·수정·삭제를 추적하는 기존 정책을 적용해야 합니다.

## 대안

- 레코드·파일 물리 삭제: 이전 버전·원본 추적 요구와 맞지 않습니다.
- 삭제 표시와 이벤트 기록: 목록에서 제외하면서 기존 파일·감사 정보를 보존합니다.

## 결정

개별 이미지 DELETE API는 dataset:image:delete와 활성 공간·ACTIVE 멤버십·공간 OWNER/ADMIN 또는 데이터셋 생성자 조건을 AND로 검사합니다. 이미지 생성자 일치 조건은 이번에 추가하지 않습니다. 사전 판정과 실제 변경 SQL에서 대상 조건을 확인하며 기존 데이터셋 행 잠금으로 교체·삭제를 직렬화합니다.

현재 활성 이미지 ID에 is_deleted=true를 기록하고 수정일시·수정자를 갱신합니다. 생성일시·생성자·버전 번호·파일 경로는 보존하며 실제 파일은 삭제하지 않습니다. 같은 트랜잭션에 DELETE 스냅샷을 추가하고 이력 실패 시 삭제 표시도 롤백합니다. 이미 삭제되거나 교체된 ID는 404이며 새 버전을 대신 삭제하지 않습니다.

프런트는 행/전체 선택·부분 선택 표시와 선택 건수·확인창·선택 삭제 버튼을 제공합니다. 요청은 이미지별 순차 호출이며 각 항목은 독립 트랜잭션입니다. 성공 행만 목록에서 제거하고 실패 행·선택을 유지합니다. 화면 종료 시 남은 요청을 중단하며 완료 여부가 불명확하면 목록 재확인을 안내합니다. 자동 재시도·새 일괄 API는 추가하지 않습니다.

## 결과

일반 목록·데이터셋 이미지 개수·원본·썸네일에서 삭제 표시 이미지를 제외합니다. 삭제 후 같은 원본명으로 신규 등록하면 새 이미지 ID·버전 1의 별도 계열이며 기존 파일·이력과 자동으로 연결하지 않습니다. 이력 탐색·복구·물리 정리 배치는 후속입니다. 기존 V20·V21과 delete 권한을 사용하므로 새 스키마·권한은 필요하지 않습니다.

현재 계약은 [API](../api/api.md#delete-apidatasetsdatasetidimagesimageid), 데이터는 [이미지](../db-schema/tables/dataset/dataset-image.md)·[이력](../db-schema/tables/dataset/dataset-image-history.md), 화면은 [스토리보드](../storyboards/image-management/README.md)를 따릅니다.
