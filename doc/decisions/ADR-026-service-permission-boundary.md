# ADR-026: 서비스 계층의 선택적 권한 검사

- 상태: 채택 (서비스 Method Security 구현)
- 날짜: 2026-11-09
- 대체/관련 기록: [권한 설계 제안](../proposals/authorization-design-proposal.md)의 컨트롤러·MVC 인터셉터 인가 및 서비스 경계 보류 방침을 대체

## 맥락

현재 권한 검사는 컨트롤러 선언을 MVC 인터셉터가 읽어 수행하므로 서비스 직접 호출 경로에는 적용되지 않습니다. 사용자는 서비스에 필요한 제한만 선언하고 권한 확인만을 위한 별도 계층은 만들지 않도록 결정했습니다.

## 대안

- 컨트롤러 인가 유지: HTTP 호출 경로에 결합됩니다.
- 권한 확인 서비스와 일반 서비스를 두 계층으로 분리: 모든 업무에 위임 구조가 추가됩니다.
- 단일 서비스 계층에서 필요한 메서드만 보호: 기능의 접근 제한을 해당 서비스에 명시합니다.

## 결정
접근 제한이 필요한 서비스 메서드에만 `@PreAuthorize`를 적용합니다. 모든 서비스에 선언을 강제하지 않으며 어노테이션 없는 서비스를 기본 거부하지 않습니다. 컨트롤러의 퍼미션 체크는 완전히 제거하고 앞으로도 추가하지 않습니다. 컨트롤러 선언을 MVC 인터셉터가 읽어 권한을 검사하는 구조도 제거 대상입니다. JWT 인증과 HTTP 요청·응답 처리는 권한 검사 위치와 구분합니다.

서비스는 단일 계층으로 유지하며 권한 확인 전용 서비스 계층이나 모든 서비스를 감싸는 공통 진입 계층은 만들지 않습니다. 기존 `AuthorizationService`의 공통 판정은 재사용할 수 있습니다. 여러 서비스를 조합할 필요가 생기면 해당 업무의 상위 서비스를 작성해 호출하고 각 서비스의 권한 검사를 유지합니다. 상위 서비스 자체의 제한도 필요한 경우에만 선언합니다. 양쪽 권한을 각각 요구하면 AND 조건이며 OR 등 다른 조건은 업무 정책으로 명시합니다.

보호 메서드는 Spring 프록시를 통해 호출하며 같은 객체 내부 호출에 `@PreAuthorize`가 적용된다고 가정하지 않습니다. 선언 누락 검출용 기동 검사기·전수 스캔·전용 검증 프레임워크는 추가하지 않습니다. 구현 시 제한 대상 서비스의 허용·거부, HTTP 외 서비스 호출, 거부 시 업무 미실행과 기존 HTTP 오류 계약을 자동 검증합니다.

2026-11-09 컨트롤러 정책 어노테이션·MVC 인가 인터셉터를 제거하고 서비스 Method Security를 적용했습니다. 기존 관리 API의 필요 권한과 401·403·500 오류 계약은 유지합니다. 비동기 인증 전달과 권한 회수 동시성은 별도 미구현 과제로 유지합니다.

### 다중 권한 업무의 호출 규칙 — 2026-11-09 구체화

다중 권한 서비스를 작성할 때는 반드시 업무별 상위 서비스를 별도 Spring 빈으로 두고, 각 보호 서비스 빈을 생성자 주입받아 호출합니다. 같은 객체 내부 호출로 보호 메서드를 조합하지 않습니다. 자기 자신 주입이나 `AopContext.currentProxy()`로 구조를 우회하지 않습니다. 각 보호 메서드의 권한 검사는 유지하며 상위 서비스에 대한 별도 제한은 필요한 경우에만 선언합니다. 이는 모든 서비스에 공통 상위 계층을 강제하는 결정이 아닙니다.

작성 절차·프록시 제약·트랜잭션 및 검증 기준은 [다중 권한 서비스 작성 가이드라인](../proposals/authorization-design-proposal.md#다중-권한-서비스-작성-가이드라인)을 따릅니다. 기존 결정을 변경하지 않고 다중 권한 조합의 구현 규칙을 구체화합니다.
## 결과

HTTP 외 호출에도 동일한 서비스 권한 제한을 적용하는 방향으로 전환합니다. 업무별 상위 서비스는 필요한 경우에만 작성합니다. 컨트롤러 정책 어노테이션·MVC 인가 인터셉터 제거와 서비스 Method Security 전환을 구현했습니다. 검증 결과는 인증 단계 문서에서 관리합니다.
