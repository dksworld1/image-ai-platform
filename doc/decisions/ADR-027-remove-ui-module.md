# ADR-027: 기존 화면·메뉴 UI 모듈 철거

- 상태: 채택
- 날짜: 2026-11-09
- 대체/관련 기록: [ADR-022](ADR-022-local-app-seed.md)·[ADR-024](ADR-024-seed-database-scope.md)의 UI 데이터 준비 방침을 대체. [ADR-026](ADR-026-service-permission-boundary.md)의 서비스 권한 검사 원칙은 유지.

## 맥락

화면 관리 필요성과 메뉴 URL의 관리 주체를 재검토했습니다. 메뉴 선택 URL은 React 코드에서 관리하고 메뉴 숨김은 렌더링 제어로 다루기로 했습니다. 사용자는 새 설계 구현 전에 기존 프런트·백엔드 UI 관련 모듈 전체를 제거하도록 요청했습니다.

## 대안

- 기존 화면·메뉴 CRUD를 수정: 폐기한 화면 접근 정책과 DB 경로 모델이 남습니다.
- 기존 UI 모듈 제거 후 재설계: 기존 연동과 데이터 모델을 분리하고 새로운 메뉴 구현은 별도 작업으로 진행합니다.

## 결정

백엔드 ui 패키지·MyBatis 매퍼·UI API와 전용 테스트를 제거합니다. 프런트의 UI API 클라이언트·타입·동적 내비게이션과 메뉴 전용 스타일을 제거합니다. 공통 레이아웃·로그인·세션 복원·로그아웃·시작 화면과 auth 모듈의 Method Security는 유지합니다. 대체 메뉴 기능은 추가하지 않습니다.

V3는 적용 이력 보존을 위해 유지하고 V4로 ui_screen_permission·ui_menu·ui_screen을 삭제합니다. 기존 공통 반복 seed의 파일명은 Flyway 이력 호환을 위해 유지하되, 01은 UI 전용 권한과 역할 연결만 삭제하고 02는 데이터 변경 없는 SELECT 1로 대체합니다. 실행 순서는 V4 DDL → 공통 01 정리 → 공통 02 무변경 → local 관리자 seed입니다. local seed는 관리자 계정·역할·현재 권한 연결만 준비합니다.

기존 화면 관리 스토리보드는 폐기 설계 이력으로 보관합니다. 새 메뉴는 React 코드의 URL 연결과 메뉴 렌더링 제어를 기준으로 추후 설계하며 서비스 권한 검사와 분리합니다.

## 결과

/api/ui 경로는 더 이상 제공하지 않으며 로그인 후 헤더와 시작 화면만 표시합니다. UI 데이터는 다음 Flyway 적용 시 삭제되어 자동 복구되지 않습니다. 적용 전 DB 백업이 필요합니다. 이번 작업에서는 실제 로컬·운영 DB를 변경하거나 자동 repair하지 않습니다. 기존 V3 체크섬 불일치가 남은 DB는 종전 정합성 절차가 선행되어야 합니다.
