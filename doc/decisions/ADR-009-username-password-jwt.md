# ADR-009: 아이디·비밀번호 로그인과 JWT

- 상태: 채택
- 날짜: 2026-11-02
- 관련 기록: [ADR-007 백엔드 모듈 경계](ADR-007-backend-modules.md), [2단계 인증과 권한](../stages/stage-02-authentication.md)

## 맥락

인증 모듈의 첫 기능으로 사용자 아이디와 비밀번호를 확인하고 후속 API가 사용할 인증 토큰을 발급해야 합니다. 백엔드는 Spring Boot REST API이며 계정 데이터는 [ADR-010](ADR-010-app-datasource.md)이 정한 `app` 데이터소스에 저장합니다.

## 결정

- Spring Security를 사용하고 API 요청은 무상태로 처리합니다.
- `POST /api/auth/token`에서 아이디와 비밀번호를 검증합니다. 비밀번호는 BCrypt 해시로 저장하고 비교합니다.
- 성공 시 JJWT 라이브러리로 HS256 서명의 JWT access token을 발급합니다. 기본 유효기간은 15분입니다.
- 모든 프로파일은 `JWT_SECRET` 환경 변수에서 서명 키를 읽고 UTF-8 기준 최소 32바이트를 요구합니다. 로컬 키는 실행 전에 현재 셸에서 만들며 저장소에는 기록하지 않습니다. 테스트는 테스트 전용 키를 테스트 설정으로 제공합니다.
- 사용자 계정은 `app` 데이터소스의 Flyway 관리 `auth_user` 테이블에서 조회합니다. 테이블은 마이그레이션으로 생성하고 계정 데이터는 자동 삽입하지 않습니다.
- 헬스체크와 로그인 경로 외의 API는 유효한 Bearer token을 요구합니다. 로그인 실패는 계정 존재 여부를 드러내지 않도록 같은 401 응답을 사용합니다.

## 결과

- 인증서버와 API 자원이 같은 애플리케이션에서 JWT를 검증하므로 별도 세션 저장소가 필요하지 않습니다.
- JWT는 만료 전까지 즉시 폐기할 수 없습니다. access token 수명을 짧게 두며 refresh token, 로그아웃 폐기 목록, 키 회전은 후속 결정으로 남깁니다.
- 가입·계정 복구·계정 초기 프로비저닝 및 역할 권한 모델은 이번 결정의 범위 밖입니다.
- 운영 환경은 `JWT_SECRET`, `app` 데이터소스 연결 설정과 `auth_user` 테이블을 안전한 배포·운영 절차로 제공해야 합니다.
