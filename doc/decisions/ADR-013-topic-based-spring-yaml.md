# ADR-013: Spring YAML 우선 및 주제별 설정 관리

- 상태: 채택
- 부분 대체(2026-11-12): [ADR-037](ADR-037-application-yaml-settings.md)에 따라 DB 외 일반 설정은 application.yaml 직접 작성으로 변경합니다. DB 접속 분리·외부 비밀정보 정책은 유지하며 아래 주제별 import 설명은 당시 결정 이력입니다.
- 날짜: 2026-11-07
- 대체/관련 기록: ADR-004, ADR-009 (환경 변수 사용 원칙 보완)

## 맥락

애플리케이션 설정 모듈 개발을 최우선으로 진행합니다. 사용자는 환경 변수를 불가피한 경우로 제한하고 Spring YAML 파일을 가능한 한 주제별로 묶어 관리하도록 요청했습니다.

## 대안

- 환경 변수 중심 관리: 배포 환경에서 주입하기 쉽지만 설정이 여러 변수로 분산됩니다.
- Spring YAML 중심 관리: 관련 설정을 주제별 파일로 묶고 Spring 설정 로딩으로 조합할 수 있습니다.

## 결정

- 백엔드 애플리케이션 설정은 Spring YAML 파일에서 관리합니다.
- 환경 변수는 피할 수 없는 경우에만 사용하며 예외 사유를 기록합니다. 비밀값이라는 이유만으로 환경 변수 사용을 기본으로 정하지 않습니다.
- YAML은 가능한 한 데이터소스·인증 등 주제별로 분리하고 `spring.config.import`로 조합합니다. 공통값과 환경별 차이를 구분하며 불필요하게 파일을 잘게 나누지 않습니다.
- 비밀값이 포함된 YAML은 저장소 밖에서 관리하고 저장소에는 비밀값 없는 예시만 둡니다.

## 결과

기존 환경 변수 사용을 설정 모듈 개발 시 검토해 YAML 전환 대상과 불가피한 예외를 정합니다. ADR-004의 외부 JDBC YAML 관리 방향은 유지하며 ADR-009의 운영 JWT 키 환경 변수 사용은 이 원칙에 따라 재검토합니다. 이번 변경은 정책과 계획 반영이며 기존 실행 설정을 전환한 것은 아닙니다.
