# ADR-028: 공통 생성·수정 컬럼과 시스템 작업자 ID

2026-11-10: 사용자 작업자의 username 기준은 [ADR-031](ADR-031-user-identity-fields.md)의 내부 user_key 기준으로 대체합니다. 공통 컬럼·시각·시스템 키 `'0'`·감사 FK 미사용 정책은 유지합니다.

- 상태: 채택
- 날짜: 2026-11-10
- 대체/관련 기록: ADR-009, ADR-023, ADR-027

## 맥락

사용자가 모든 테이블에 생성일·수정일·생성자·수정자를 추가하고 기존 스키마·SQL·백엔드를 함께 변경하도록 요청했습니다. 시스템 작업자 ID는 사용자의 명시적 결정으로 `'0'`을 사용합니다. 현재 사용자 식별자는 문자열 `username`이며 기존 DB의 적용된 Flyway 이력을 보존해야 합니다.

## 대안

- 문자열 `system`: 의미는 읽기 쉽지만 반복 저장 값이 더 깁니다.
- 문자열 `'0'`: 현재 사용자 식별자 계약을 유지하면서 시스템 값을 짧게 표현합니다. 사용자 아이디 예약이 필요합니다.
- 숫자 작업자 키: 별도 사용자 키 전환과 참조 구조 변경이 필요해 이번 범위에 포함하지 않습니다.

## 결정

모든 프로젝트 소유 테이블에 NOT NULL인 `created_at`, `updated_at`, `created_by`, `updated_by`를 둡니다. 시간은 `TIMESTAMP WITH TIME ZONE`과 `OffsetDateTime`, 작업자는 `VARCHAR(100)`과 `String`으로 표현합니다. 사용자 작업은 서버가 확인한 username, 시스템 작업은 문자열 `'0'`을 기록합니다. `'0'` 사용자 계정은 CHECK 제약으로 금지하며 시스템 로그인 계정과 작업자 FK는 만들지 않습니다.

생성 시 생성·수정 정보를 함께 기록하고 UPDATE는 생성 정보를 보존하며 수정 정보만 갱신합니다. INSERT 기본값은 현재 시각과 `'0'`이며 사용자 작업은 작업자를 명시합니다. 자동 감사 프레임워크·트리거·기동 스캔은 추가하지 않습니다. 상세 기준은 [공통 스키마 생성 규칙](../db-schema/schema-rules.md)을 따릅니다.

기존 V1~V4는 보존하고 V5에서 app 5개 테이블에 컬럼을 추가합니다. 기존 행은 적용 시각과 `'0'`으로 보정하며 과거 이력으로 해석하지 않습니다. legacy probe는 DB별 수동 ALTER SQL과 테스트 fixture를 갱신합니다. 폐기된 UI 테이블과 외부 도구 소유 이력 테이블은 변경하지 않습니다.

## 결과

신규 테이블과 기존 최종 스키마가 동일한 메타데이터 계약을 따릅니다. Java record 및 MyBatis 매핑과 seed를 함께 갱신합니다. 생성·최종 수정만 기록하므로 별도 전체 감사 이력은 제공하지 않습니다.

실제 DB 적용 전 백업과 `'0'` 계정 존재 여부 확인이 필요합니다. legacy probe는 새 SQL이 자동 실행되지 않으므로 DAO 사용 전에 운영자가 적용해야 합니다. 실제 로컬·운영 DB 적용은 별도 절차이며 이번 변경은 코드와 격리된 테스트 DB로 검증합니다.
