# ADR-033: 데이터셋의 다중 워크스페이스 연결과 목록 조회

- 상태: 대체됨 — [ADR-034](ADR-034-independent-dataset-creation.md)의 공간별 독립 생성으로 변경. 아래는 공유 방식 이력
- 날짜: 2026-11-11
- 대체/관련 기록: [ADR-032](ADR-032-workspace-data-boundary.md)의 단일 공간 FK·최종 NOT NULL 방침을 대체. 공간·멤버십·소유자 모델은 유지. [ADR-030](ADR-030-dataset-creation-contract.md)의 인증 전용 생성 계약은 아래 권한·공간 필수 계약으로 변경.

## 맥락

사용자는 내가 가입한 워크스페이스들의 데이터셋을 한 목록에서 확인하고, 생성 시 체크박스 드롭다운으로 여러 공간을 선택하도록 요청했습니다. admin 소유의 두 번째 local 공통 공간도 요청했습니다.

## 대안

- 공간마다 데이터셋을 복제: 이름·설명과 향후 데이터가 서로 달라질 수 있습니다.
- 데이터셋 한 행에 공간 ID 배열 저장: 공간 FK·중복 제약을 관계형 테이블로 표현하기 어렵습니다.
- 데이터셋 한 개와 공간 연결 테이블: 데이터를 복제하지 않고 여러 공간에서 공동 사용합니다.

## 결정

`dataset_workspace`를 추가하여 하나의 데이터셋을 여러 공간에 연결합니다. V11에서 구조 생성, common DML V12에서 기존 단일 공간·감사 정보를 보존해 이관, V13에서 기존 컬럼·FK·인덱스를 제거합니다. V10 등 과거 SQL은 유지합니다. 미귀속 데이터는 임의 배정하지 않습니다.

생성에는 `dataset:item:create`와 선택한 모든 공간의 ACTIVE 멤버십·활성 공간을 요구합니다. 서비스 `@PreAuthorize`에 두 조건을 명시합니다. 공간은 하나 이상 필수이며 중복 ID는 제거합니다. 데이터셋과 모든 연결의 ID·시각·작업자는 서버에서 생성하고 한 트랜잭션으로 저장합니다. 존재하지 않는 공간·접근할 수 없는 공간이 하나라도 있으면 전체 요청을 거부합니다.

목록은 `dataset:item:read`를 명시적으로 검사하고 SQL에서 현재 사용자 내부 user_key의 ACTIVE 멤버십과 ACTIVE 공간을 결합합니다. 다른 생성자의 데이터도 해당 공간에 연결되어 있으면 조회합니다. 여러 가입 공간에 연결된 동일 데이터셋은 한 번만 표시하고, 응답에는 사용자가 접근 가능한 연결 공간만 포함합니다. 미가입 공간의 이름·ID도 노출하지 않습니다. 멤버십 회수 후 다음 요청에는 반영하며 이미 시작된 동시 작업까지 직렬화하는 정책은 별도입니다.

local 초기 공간은 고정 UUID 끝자리 001·002 두 개입니다. 두 공간 모두 로그인 admin의 실제 내부 user_key를 소유자·ACTIVE ADMIN 멤버로 사용합니다. 기존 seed 행은 재실행 시 덮어쓰지 않습니다.

## 결과

현재 제공하는 API는 가입 공간 목록, 데이터셋 목록과 다중 공간 생성입니다. 전체 결과를 최신 생성순으로 반환하며 페이지·검색·필터·상세·수정·삭제·공간 관리 화면은 추가하지 않았습니다. 향후 공동 데이터의 변경·삭제가 여러 공간에 영향을 주는 권한 정책은 해당 기능 구현 전에 별도로 확정합니다. 이번 목록 접근은 변경 권한을 의미하지 않습니다.

API·DB 상세는 [API 계약](../api/api.md#데이터셋-목록), [연결 테이블](../archive/dataset-sharing/dataset-workspace.md)을 기준으로 관리합니다. 실제 DB 적용·서버 재시작은 하지 않았습니다.
