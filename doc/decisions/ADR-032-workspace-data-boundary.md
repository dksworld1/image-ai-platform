# ADR-032: 워크스페이스 데이터 귀속과 멤버십 모델

- 상태: 채택 — V10 DDL·local 초기 데이터 구현, 업무 기능 후속
- 부분 대체: [ADR-033](ADR-033-dataset-multiple-workspaces.md)이 dataset의 단일 공간 FK·최종 NOT NULL 방침을 다대다 연결로 대체합니다. 공간·멤버십 모델은 유지합니다.
- 현재 귀속 결정: [ADR-034](ADR-034-independent-dataset-creation.md)에서 단일 공간 FK를 복원하고 다중 선택은 공간별 독립 생성으로 변경했습니다. 과거 미귀속 데이터가 있어 현재 FK는 nullable입니다.
- 날짜: 2026-11-11
- 대체/관련 기록: [ADR-026](ADR-026-service-permission-boundary.md), [ADR-028](ADR-028-common-audit-columns.md), [ADR-031](ADR-031-user-identity-fields.md)

## 맥락

사용자는 여러 워크스페이스에 신청하고 관리자 승인 후 참여합니다. 같은 공간의 데이터셋을 함께 다루되 사용·수정·삭제 기능 권한도 별도로 검사해야 합니다. 생성자 감사 정보로 데이터 접근 범위를 대신할 수 없습니다.

## 대안

- 사용자별 생성자 필터: 공동 데이터 조회 요구를 충족하지 못합니다.
- 사용자당 한 공간: 다중 가입 요구를 충족하지 못합니다.
- 조직·그룹 계층과 데이터별 ACL: 현재 요구보다 구조·관리 범위가 큽니다.
- 공간·멤버십 두 테이블과 데이터셋 공간 FK: 현재 요구를 직접 표현하며 기존 RBAC를 재사용할 수 있습니다.

소유자를 멤버의 OWNER 역할에 저장할 수도 있지만 공간별 정확히 한 명이라는 조건을 별도로 보장해야 합니다. 공간 행에 단일 소유자 FK를 두면 존재·단일성은 일반 FK와 NOT NULL로 표현할 수 있습니다.

## 결정

`workspace`, `workspace_member`를 추가하고 `dataset.workspace_id`를 최종 필수 FK로 둡니다. 멤버십 PK는 `(workspace_id, user_key)`이며 가입 상태와 최근 승인 정보만 보존합니다. 별도 가입 신청·이력·데이터셋별 권한 테이블은 추가하지 않습니다.

소유자는 `workspace.owner_user_key`를 단일 기준으로 삼고 멤버 역할은 ADMIN·MEMBER로 구분합니다. 이전 제안의 OWNER·ADMIN·MEMBER 중 OWNER 표현을 소유자 컬럼으로 구체화하는 안입니다. 소유자도 ACTIVE·ADMIN 멤버십을 유지해야 하며 생성·이전·탈퇴 처리를 트랜잭션으로 묶습니다. ACTIVE 멤버십까지 DB FK 하나로 보장된다고 간주하지 않습니다.

서비스 `@PreAuthorize`에 기능 권한 코드를 명시하고 공간·대상 접근 조건을 AND로 결합합니다. 전역 역할과 공간 역할을 혼용하거나 OWNER에게 기능 권한을 자동 부여하지 않습니다. 테이블의 상세 기준은 [워크스페이스 테이블 설계](../db-schema/tables/workspace/README.md)에 둡니다.

## 결과

2026-11-11 테이블 설계 승인과 SQL·local seed 작성 요청에 따라 V10과 local 초기 데이터를 구현했습니다. admin 소유의 공통 공간과 ACTIVE·ADMIN 멤버십을 local에만 준비합니다. 기존 데이터셋을 임의 배정하지 않으므로 공간 FK는 전환 기간 동안 nullable이며 NOT NULL 적용은 후속 작업입니다. 실제 DB에는 적용하지 않았습니다.

워크스페이스 관리 화면과 업무 API는 후속 구현입니다. 공간 개설·검색 공개·공간 내 작업 허용 역할·기존 데이터 귀속 정책은 해당 구현 전 확정해야 합니다. 데이터별 사용자 공유 또는 전체 가입 이력이 실제 요구가 되면 별도 설계합니다.
