# ADR-007: 백엔드 모듈 경계

- 상태: 채택
- 날짜: 2026-11-02
- 대체/관련 기록: ADR-006 백엔드 패키지 역할 경계

## 맥락

백엔드 기능 구현을 시작하기 전에 인증·권한과 이미지 데이터셋의 책임 경계를 분명히 할 필요가 있습니다. 기존 ADR-006은 역할별 최상위 패키지를 정했지만, 기능이 늘어날 때 모듈 경계를 직접 표현하지는 않습니다. 현재 단계에서는 빌드·배포 단위를 나눌 필요가 없습니다.

## 대안

- 기능별 패키지 아래에서 역할을 구분합니다. 한 기능의 코드와 책임이 모이며 기존 역할 규칙도 유지할 수 있습니다.
- 역할 패키지 아래에서 기능별 하위 패키지를 둡니다. 기존 구조와 가까우나 기능 경계가 여러 최상위 패키지에 흩어집니다.
- Maven 서브모듈로 기능을 나눕니다. 빌드 경계를 강제할 수 있으나 초기 기능 단계에서 설정 복잡성이 추가됩니다.

## 결정

- 단일 Spring Boot 애플리케이션과 단일 배포 단위를 유지하는 모듈러 모놀리스를 사용합니다.
- 업무 기능 모듈은 `com.imageaiplatform.auth`와 `com.imageaiplatform.dataset`으로 둡니다.
- 각 모듈 안에서 `controller`, `service`, `dao`, `domain` 역할 패키지를 구분합니다. DAO 계약은 `dao` 바로 아래, 구현체는 `dao.impl` 아래에 둡니다.
- 모듈 간 호출은 서비스 경계를 통하고, 상대 모듈의 DAO·구현 세부사항·도메인 객체를 직접 참조하지 않습니다.
- 이번 변경은 패키지 뼈대 생성에 한정합니다. 기존 기반 코드의 이동, 업무 클래스 생성, Maven 모듈 분리는 하지 않습니다.

## 결과

- 기능별 책임과 기존 역할별 책임을 함께 드러내는 패키지 구조를 사용합니다.
- 지금은 경계를 패키지와 코드 리뷰 규칙으로 관리합니다. 모듈 간 의존을 빌드 시 강제해야 할 필요가 생기면 Maven 서브모듈 전환을 재검토합니다.
- ADR-006의 역할 경계는 모듈 내부에 계속 적용합니다. 기존 클래스의 패키지 이동은 이 결정의 범위에 포함하지 않습니다.
