# ADR-039: 이미지 교체 버전과 작업 이력 보존

- 상태: 채택
- 날짜: 2026-11-13
- 대체/관련 기록: ADR-036·038 확장. 일반 업로드 중복 거부는 유지
- 후속 결정: [ADR-040](ADR-040-image-permissions.md)이 이미지 읽기·수정 기능 권한을 분리했습니다. 아래 동일 업로드 권한 재사용 설명은 당시 결정이며 버전·이력 보존은 유지합니다.

## 맥락

사용자는 수정 업로드에서 동일 데이터셋·원본명의 이미지를 교체하되 이전 레코드와 파일을 지우지 않고 버전을 증가시키며 생성·삭제·수정 작업자를 추적하도록 요청했습니다.

## 대안

- 같은 파일과 행을 덮어쓰기: 구현은 단순하지만 이전 원본·메타데이터가 사라집니다.
- 파일 버전별 행과 별도 이벤트 이력: 저장량은 증가하지만 이전 파일·등록자와 교체 작업자를 보존합니다.

## 결정

일반 업로드는 현재 활성 원본명이 중복되면 409입니다. 명시적 수정 업로드는 기존 행을 is_deleted=true로 변경하고 새 UUID의 이미지 행·원본·썸네일을 추가합니다. 최초 version_count=1, 교체는 직전 버전+1이며 previous_image_id로 연결합니다. 일치하는 현재 이미지가 없으면 최초 등록합니다. 동일 요청을 다시 보내면 새 버전이 되므로 자동 재시도하지 않습니다.

현재 활성 원본명만 DB UNIQUE로 보장하고 데이터셋 행 잠금으로 동시 등록·교체·데이터셋 삭제를 직렬화합니다. 기존 업로드 기능 권한과 활성 공간 멤버십·운영자/데이터셋 생성자 조건을 재사용하며 별도 퍼미션을 추가하지 않습니다. 교체 전 기존 행의 생성 감사 값은 보존하고 삭제 표시의 수정 감사 값만 교체자로 갱신합니다. 새 파일 행은 새 등록 시각·등록자를 기록합니다.

dataset_image_history에는 CREATE, UPDATE, DELETE 이벤트와 버전 메타데이터·원래 행의 감사 값을 스냅샷으로 남깁니다. 교체는 이전 버전 DELETE와 새 버전 UPDATE, 신규 파일은 CREATE입니다. V21은 과거 이미지를 BASELINE으로 기록하며 알 수 없는 과거 변경 이력을 생성하지 않습니다. 상태 전환·신규 행·이력은 하나의 DB 트랜잭션이고 실패 시 신규 파일만 정리합니다.

데이터셋 삭제의 기존 FK CASCADE 정책은 유지하되 서비스에서 현재 이미지의 DELETE 이력을 먼저 남깁니다. 이력에는 부모 FK를 두지 않아 데이터셋 삭제 후에도 작업자·시각·파일 위치가 보존됩니다. 일반 조회·개수·원본/썸네일 API는 삭제 표시 버전을 제외합니다. 직접 SQL 작업은 서비스 이력을 생성하지 않습니다.

## 결과

이전 원본과 썸네일을 보관하므로 디스크·DB 사용량이 증가합니다. 이번 범위는 이력 저장이며 이력 조회 화면·복구·개별 이미지 삭제 API·파일 정리 배치는 포함하지 않습니다. 원본 확인은 현재 버전의 권한 있는 content API와 상세 모달로 제공합니다. 파일 시스템과 DB는 분산 트랜잭션이 아니므로 프로세스 중단 시 남은 신규 파일 정리는 여전히 별도 과제입니다.
