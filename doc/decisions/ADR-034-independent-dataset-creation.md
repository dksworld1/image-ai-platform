# ADR-034: 워크스페이스별 독립 데이터셋 생성

- 상태: 채택 — 구현·선별 검증 완료, 실제 DB 미적용
- 날짜: 2026-11-11
- 대체/관련 기록: [ADR-033](ADR-033-dataset-multiple-workspaces.md)의 공유 데이터셋·다대다 연결 방침을 대체. [ADR-032](ADR-032-workspace-data-boundary.md)의 공간·멤버십·소유자 모델 유지.

## 맥락

사용자는 여러 공간을 선택할 때 같은 데이터셋을 공유하는 대신 공간마다 독립 데이터셋을 생성하도록 변경했습니다. 공간별 수정·삭제가 다른 공간의 데이터에 영향을 주지 않아야 합니다.

## 대안

- 하나의 데이터셋 공유: 수정·삭제가 여러 공간에 영향을 주므로 현재 요구와 다릅니다.
- 공간별 독립 데이터셋: 저장 행·ID와 이후 데이터 수명 주기를 분리할 수 있습니다.

## 결정

생성 요청은 workspaceIds 배열을 유지하고 중복 공간 ID를 제거한 뒤 공간마다 새 dataset_id를 발급합니다. 생성된 각 행은 하나의 workspace_id만 가집니다. 입력 이름·설명과 요청 단위 생성·수정 시각·작업자는 동일하며 결과는 데이터셋 배열로 반환합니다. 전체 선택 공간의 멤버십과 create 기능 권한을 먼저 확인하고 한 app 트랜잭션에서 모두 저장합니다. 일부 성공 응답은 제공하지 않습니다.

목록은 가입 승인된 활성 공간 기준을 유지하고 공간별 독립 데이터를 각각 한 행으로 표시합니다. 같은 이름이더라도 ID·귀속 공간이 다릅니다. 그룹화와 다대다 연결은 제거합니다. 체크박스 드롭다운에는 “선택한 공간마다 독립 데이터셋이 생성됩니다”를 안내합니다.

V14 DDL로 단일 공간 FK·인덱스와 이관용 임시 연결 컬럼을 준비하고 common DML V15에서 기존 공유 데이터를 분리한 뒤 V16에서 연결 테이블을 제거합니다. 기존 ID는 공간 ID 오름차순 첫 공간에 보존하고 나머지 공간은 새 UUID를 발급합니다. 이름·설명·감사 값은 보존하고 미귀속 데이터는 그대로 둡니다. 과거 V1~V13과 이력은 변경하지 않습니다.

## 결과

추가 사용자 확인: local의 과거 미귀속 데이터만 V17 일회성 DML로 첫 번째 공통 공간에 배정합니다. 기존 공간이 지정된 데이터의 귀속은 유지합니다. 생성 정보는 보존하고 수정 정보는 이관 작업으로 갱신합니다. 실제 DB 적용은 하지 않았습니다.

현재 생성은 빈 데이터셋의 기본 정보만 공간별로 복제합니다. 향후 이미지가 있는 데이터셋 복제 기능을 추가한 것은 아닙니다. 목록의 기능 권한·활성 멤버십 검사와 admin 소유의 local 두 공간은 유지합니다. 관리 화면·상세·수정·삭제는 후속이며 실제 DB 적용은 하지 않았습니다.

현재 계약은 [API](../api/api.md#데이터셋-생성)와 [dataset 정의](../db-schema/tables/dataset/dataset.md), 적용은 [마이그레이션 절차](../operations/database-migration.md#공간별-독립-데이터셋-v14v15v16--2026-11-11)를 따릅니다.
