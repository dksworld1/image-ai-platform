# `foundation_probe` 테이블 정의

- 그룹: 기반
- 데이터소스: legacy `catalog`, `archive` (자동 생성 없음, fixture 또는 사전 DB 프로비저닝 필요)
- 스키마 프로비저닝: 애플리케이션 자동 생성 없음. 기존 테이블에는 `db/migration/catalog/V1__add_common_audit_columns.sql`, `db/migration/archive/V1__add_common_audit_columns.sql`을 각 DB에 수동 적용
- 사용 코드: `com.imageaiplatform.foundation.dao.FoundationProbeDao`

## 목적

기반 데이터 접근과 데이터소스 연결을 확인하는 예제 테이블입니다. 제품 업무 데이터 저장에는 사용하지 않습니다.

## 컬럼

| 컬럼 | 형식 | NULL | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | `BIGINT IDENTITY` | 아니요 | 자동 증가 | 레코드 식별자, 기본 키 |
| `probe_value` | `VARCHAR(100)` | 아니요 | 없음 | 연결·트랜잭션 검증 값 |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | 아니요 | `CURRENT_TIMESTAMP` | 생성일 |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | 아니요 | `CURRENT_TIMESTAMP` | 최종 수정일 |
| `created_by` | `VARCHAR(100)` | 아니요 | `'0'` | 생성자, 시스템 작업은 문자열 `'0'` |
| `updated_by` | `VARCHAR(100)` | 아니요 | `'0'` | 최종 수정자, 시스템 작업은 문자열 `'0'` |

[공통 스키마 생성 규칙](../../schema-rules.md)에 따라 생성 정보를 보존하고 수정 정보만 갱신합니다.

## 제약 및 인덱스

- 기본 키: `id`
- 추가 인덱스 및 유일성 제약 없음

## 신규 테이블 프로비저닝 DDL

아래 DDL을 catalog/archive 각각의 사전 프로비저닝에서 적용합니다. 기존 테이블에는 신규 생성 대신 DB별 V1 ALTER 파일을 한 번 적용합니다. 두 파일은 기본 Flyway 위치 목록에 포함하지 않습니다.

```sql
CREATE TABLE foundation_probe (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    probe_value VARCHAR(100) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(100) NOT NULL DEFAULT '0',
    updated_by VARCHAR(100) NOT NULL DEFAULT '0'
);
```
